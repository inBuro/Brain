# Skill Optimizer — Pin Mode

Статус: **реализовано** (2026-08-29) — `PinnedPanelController.swift` + тоггл в футере `SkillDensityMenu.swift`.
Проверено вручную: открытие/закрытие панели, позиция, непрозрачный фон, повторный клик по иконке мунбара
поднимает уже открытую панель вместо второй, отмена пина изнутри панели. Не проверено автоматизацией:
закрытие по Esc (реализовано через `NSEvent` local monitor, логика та же, что у остальных путей закрытия).

Гипотеза из раздела 3 («`.popover` внутри настоящего окна ведёт себя предсказуемее, чем внутри
`MenuBarExtra`») **не подтвердилась** — то же расхождение попапа описания от строки воспроизвелось и
внутри `NSPanel`. Не мешает самой фиче (детач + always-on-top работают правильно), но как аргумент
«почему это чинит баг с попапом» — снят; см. обновлённую находку №1 в `research/audit/audit_report.md`.
Смежно: баг с `DescriptionPopover` (рендер оторван от строки) — не одно и то же, но вдохновил

---

## Зачем

Сейчас попап — трансиентный: открылся по клику на иконку, закрылся при клике мимо. Это правильный
дефолт. Но иногда нужно держать список скиллов постоянно видимым, пока работаешь в других окнах.
Pin mode даёт это одним действием, без нового «режима» и без второй точки входа.

---

## Что решено (не переоткрывать)

- **Один тоггл** — и «открепить от transient lifecycle», и «всегда поверх других окон» — это одно
  действие, не два. Отдельный «detach» без «always-on-top» бесполезен для этой утилиты.
- Реализуется через отдельный `NSPanel` (floating window level), разделяющий тот же `SkillDensityModel`.
  Это не патч поверх существующего `MenuBarExtra`, а второй настоящий объект окна.

---

## 1. Где живёт пин-контрол

**Место: футер, вплотную слева от «⌘Q Quit».**

Текущий футер:
```
[ Updated: 12:34:56  ↻ ]     ......Spacer......     [ ⌘Q  Quit ]
```

После добавления:
```
[ Updated: 12:34:56  ↻ ]     ......Spacer......     [ ⌑ ]  [ ⌘Q  Quit ]
```

Почему не хедер:
- Хедер отвечает за «что смотрим» (таймфрейм + сортировка). Pin — это управление окном, другой
  семантический слой.
- Хедер уже плотный: 276px inner = растянутый пикер + 8px gap + 44px sort-кнопка. Ещё один элемент
  сожмёт пикер без выигрыша в удобстве.

Почему рядом с «Quit»:
- «Quit» и «Pin» — оба lifecycle-контрола приложения. Логическая группа.
- Spacer в футере поглощает пространство без перекомпоновки.
- Тихое место: пин не нужен постоянно, не должен отвлекать.

Размер: иконка SF Symbols `pin` / `pin.fill`, 11pt — тот же масштаб, что стрелка рефреша (`11` в коде).
Кнопка plain-style, без фона, без рамки. Пустой `.padding(.trailing, 8)` отделяет от «⌘Q».

## 2. Визуальные состояния

### Unpinned (дефолт)

- Иконка: `pin` (outline), `.foregroundStyle(.secondary).opacity(0.4)` — тот же приглушённый тон,
  что у «⌘Q» модификатора.
- Tooltip (`.help(...)`): `"Pin to float above other windows"`.
- Поведение окна: без изменений — трансиентный попап, закрывается кликом мимо.

### Pinned (активный)

- Иконка: `pin.fill`, `.foregroundStyle(.white)` — полная яркость, сигнализирует «активно».
- Tooltip: `"Unpin — click to close floating window"`.
- Поведение окна: `MenuBarExtra`-попап закрывается, вместо него появляется `NSPanel` с тем же
  контентом. Панель:
  - Window level `.floating` (поверх обычных окон, под модальными).
  - `styleMask: [.borderless, .nonactivatingPanel]` — никакого title bar, никаких traffic lights.
    Форма и размеры идентичны трансиентному попапу (300px wide, тот же `scrollHeight`).
  - Позиция при первом пине: там, где обычно появляется попап (под иконкой menu bar).
    При повторном пине после закрытия — та же позиция (не запоминается между запусками).
  - `NSPanel.isMovableByWindowBackground = true` — пользователь может перетащить за любое место
    в окне, не только за titlebar.

### Закрытие pinned-окна

Три пути, все делают одно: убирают NSPanel, возвращают поведение к трансиентному, меняют иконку
обратно на `pin` outline.

1. Клик по `pin.fill` в футере пинованного окна (основной способ — симметрично открытию).
2. `Esc` — стандартный macOS жест для утилитных панелей.
3. Клик по иконке в menu bar, пока окно уже пиновано (см. секцию 3).

Отдельная кнопка ✕ внутри окна **не нужна**: три пути выше покрывают всё без лишнего хрома.
Панель `borderless` — нет стандартного traffic-light corner, нет артефактов.

## 3. Lifecycle / edge cases

### Клик по иконке menu bar, пока окно пиновано

→ `NSPanel.orderFront(nil)` + `NSApp.activate(ignoringOtherApps: true)`.
Второй экземпляр попапа не открывается. Это как «show» в доке — фокус на уже открытое.
Если окно свёрнуто/скрыто пользователем — возвращает на экран.

### DescriptionPopover в pinned mode

Отдельный «pin для попапа описания» — нет. Попап описания остаётся тем же `.popover`-компонентом,
прикреплённым к строке внутри уже настоящего NSPanel-окна. В контексте реального окна (не
MenuBarExtra-bezel) `.popover` ведёт себя предсказуемо и рендерится корректно — именно поэтому баг
с оторванным попапом в трансиентном режиме вдохновил эту фичу.

Если пользователь открыл описание скилла, а затем открепил окно — попап закрывается вместе со
сменой контекста окна. Это приемлемый trade-off, усложнять переходы не нужно.

### Фоновые процессы пока окно пиновано

Всё работает штатно: refresh-таймер тикает, `UserDefaults`-запись acknowledge срабатывает по клику,
живые счётчики обновляются. Shared `SkillDensityModel` — один объект на оба окна (MenuBarExtra +
NSPanel), изменения в нём обоим видны немедленно через `@ObservableObject`.

### ⌘Q из pinned-окна

Завершает процесс целиком. Стандартно. NSPanel не делает из ⌘Q «просто закрой окно».

### Перезапуск приложения

Pinned-состояние **не сохраняется** между запусками — всегда стартует в unpinned.

Почему: transient-попап — ожидаемый дефолт. Сохранённый pin при перезапуске означает, что утилита
выскочит поверх всего сразу после логина, без намерения пользователя. Это сюрприз в плохом смысле.
UserDefaults для этого не используем.

## 4. Что НЕ меняется

- Дефолтное поведение без пина: клик на иконку → попап → клик мимо → закрылся. Без изменений.
- Размеры и внутренняя компоновка попапа: 300px, тот же `scrollHeight`, те же отступы.
- Хедер: пикер таймфрейма + sort-кнопка — без изменений, без уплотнения.
- Все существующие взаимодействия: acknowledge (+N), description popover, add/delete triggers,
  Delete Skill, refresh, ⌘Q.
- LaunchAgent автозапуска и прочая инфраструктура — не затронуты.

## Открытые вопросы (не блокируют спек, решаются при реализации)

- Как именно `MenuBarExtra` отдаёт управление при появлении NSPanel — проверить через
  `MenuBarExtraCustomContent` onAppear/onDisappear или через `NSStatusItem` напрямую.
- Нужно ли добавить `collectionBehavior: [.canJoinAllSpaces]` к NSPanel, чтобы панель не
  терялась при переключении Spaces — скорее да, это стандарт для utility-панелей macOS.
