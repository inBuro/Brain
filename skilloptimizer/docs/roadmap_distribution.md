# Skill Optimizer — roadmap: аккаунт разработчика + инфраструктура обновлений

Контекст: сейчас `scripts/deploy.sh` собирает, ad-hoc подписывает и разворачивает приложение прямо на этой же
машине — обновление всегда локальное, без сети. Автообновление в духе BatFi (проверка версии на сервере,
скачивание, установка) требует полноценной цепочки подписи + хостинга, которой сегодня нет. Это roadmap для
её разворачивания — шаг к публичному релизу (открытый вопрос из `research/brief.md`).

## Фаза 1 — Apple Developer Program

Только владелец: регистрация требует Apple ID, 2FA и оплату, я не могу пройти это за него.

- [ ] Зарегистрироваться на developer.apple.com — $99/год. Individual-аккаунт обычно одобряется почти сразу;
  Organization требует D-U-N-S номер и подтверждение юрлица (дни-недели) — для личного проекта имеет смысл
  Individual, если нет отдельного юрлица под это.
- [ ] Убедиться, что оплата и налоговые/банковские данные привязаны (Apple иногда требует их отдельно от
  App Store Connect — уточнить на месте).

## Фаза 2 — Сертификаты подписи и нотаризация

Технически исполнимо мной, но требует доступа к Developer-порталу (Kirill логинится / выдаёт API-ключ).

- [ ] Создать CSR (Certificate Signing Request) через Keychain Access.
- [ ] В Certificates, Identifiers & Profiles создать **Developer ID Application** сертификат — заменит текущую
  ad-hoc подпись в `deploy.sh`.
- [ ] Пересмотреть Bundle ID `brain.kirill.skilloptimizer` перед публичным релизом — сейчас это личный
  namespace-префикс; смена ID после релиза ломает существующие инсталляции (LaunchAgent, `UserDefaults` —
  та же проблема, что уже решалась миграционным шимом при ребрендинге, см. `CLAUDE.md`). Решить один раз,
  до первого публичного билда, не после.
- [ ] Создать App Store Connect API Key (или App-specific password для Apple ID) — нужен для
  `xcrun notarytool submit`.
- [ ] Обновить `scripts/deploy.sh` / завести отдельный `scripts/release.sh`:
  build → codesign (Developer ID, не ad-hoc) → zip → `notarytool submit --wait` → `stapler staple`.

## Фаза 3 — Интеграция Sparkle

Полностью на мне, не требует ручных шагов владельца кроме ревью.

- [ ] Добавить Sparkle как SPM-зависимость (`https://github.com/sparkle-project/Sparkle`).
- [ ] Сгенерировать EdDSA-ключ через `generate_keys` (входит в Sparkle) — приватный ключ в Keychain,
  публичный — в Info.plist (`SUPublicEDKey`). Это отдельная подпись от кода Apple, только для апдейтов.
- [ ] Info.plist: `SUFeedURL` (адрес будущего `appcast.xml`), `SUEnableAutomaticChecks`,
  `SUScheduledCheckInterval`.
- [ ] Подключить `SPUStandardUpdaterController` в `AppDelegate.swift`.
- [ ] Добавить пункт «Check for Updates…» — сейчас у приложения нет обычного app-меню (только
  `NSStatusItem`+попап), нужно решить, куда именно он ляжет — в футер попапа, или завести отдельный
  контекстный right-click меню на иконке.

## Фаза 4 — Хостинг релизов и appcast

Открытый вопрос: **где хостить** `appcast.xml` + версионные `.zip`.

- **GitHub Releases** — стандартная, наиболее документированная пара со Sparkle, ничего дополнительно
  разворачивать не надо, appcast можно отдавать сырым файлом из репозитория.
- **Cloudflare** — уже есть аккаунт и паттерн (Fadercraft/GrooveMix используют CF Pages/Workers), но под это
  придётся отдельно завести Pages-проект и вручную поддерживать выкладку файлов вместо готового
  release-флоу GitHub.

Рекомендация: начать с GitHub Releases — меньше новой инфраструктуры, дальше можно перевезти на Cloudflare,
если появится причина (напр. если репозиторий останется приватным, а релизы должны быть публичными отдельно).

- [ ] Решить хостинг (см. выше).
- [ ] Сгенерировать первый `appcast.xml` через `generate_appcast` (входит в Sparkle) по папке с релизными zip.
- [ ] Выложить первый релиз + appcast, прописать `SUFeedURL` на реальный адрес.

## Фаза 5 — Сквозная проверка

- [ ] Собрать тестовую версию с заниженным номером версии, указать `SUFeedURL` на appcast с более новой —
  убедиться, что диалог обновления (как у BatFi) появляется, скачивает и переустанавливает корректно.
- [ ] Проверить путь "нет сети" / "appcast недоступен" — приложение не должно падать или зависать.

## Открытые вопросы

- Individual vs Organization Apple-аккаунт — зависит от того, планируется ли юрлицо под публичный релиз.
- Bundle ID: оставить `brain.kirill.skilloptimizer` или сменить на нейтральный — решить в Фазе 2, до первого
  подписанного билда.
- Хостинг appcast: GitHub Releases (рекомендовано) vs Cloudflare — см. Фазу 4.
