# Skill Optimizer — что умеет приложение

## Сбор данных

- Сканирует все транскрипты Claude Code (`~/.claude/projects/**/*.jsonl`) — работает для любого клиента:
  `claude-desktop`, `claude-vscode`, `sdk-cli` (обычный терминал). Другие ассистенты (Gemini, ChatGPT/Codex
  и т.д.) в принципе не видит — у них нет понятия «скилл» в этом виде и свой формат хранения сессий.
- Считает прямые вызовы инструмента `Skill`.
- Дополнительно детектит **подскиллы**, вызванные через паттерн «роутер → `Read` файла подскилла»:
  если роутер (`seo`) только что был вызван и следующим действием читает `.../subskills/<имя>/SKILL.md` —
  это засчитывается как использование `<имя>`, хотя формального вызова `Skill` не было.
- Схлопывает легаси-адресацию: `router:subskill` (старый формат прямого вызова подскилла) и `interfaces:*`
  (бывший вендорский плагин-префикс) — сводятся к голому имени подскилла, чтобы не плодить дубли строк.
- Кэш по mtime файла: при повторном скане нетронутые транскрипты не перечитываются — пересканирование
  после первого полного прохода почти бесплатно.
- **Показывает только реально существующие сегодня скиллы.** Если файл `SKILL.md` когда-то был удалён —
  историческая активность по нему в списке не отображается (кроме встроенных системных скиллов Claude Code —
  их вообще нельзя проверить на существование, т.к. у них никогда не было файла на диске).

## Основной список

- Группировка: подскиллы вложены под своим роутером с отступом; у заголовка роутера нет собственного
  счётчика, если у него есть дочерние записи (счётчик показывают только сами вызовы).
- Три таймфрейма — **24 hours / Week / Month** — переключаются мгновенно (пересчёт из уже загруженных
  в память событий, без нового скана диска).
- Переключатель сортировки — по активности (убывание счётчика, статичный текст-иконка «321») или по
  алфавиту (текст-иконка «ABC»).
- У каждой строки — серый счётчик «всё время» и, если в выбранном таймфрейме были новые вызовы, зелёный
  `+N`. Клик по зелёному числу — «подтвердить»: счётчик гаснет и остаётся погашенным даже после перезапуска
  приложения (сохраняется в `UserDefaults`), следующий реальный вызов скилла снова покажет `+1`.
- Клик по названию скилла (со стрелкой `›` справа) открывает попап с описанием — только если для скилла
  нашёлся файл на диске.

## Попап описания скилла

- Показывает основной текст `description:` из `SKILL.md`.
- Если в описании есть маркер «Триггеры:» — выводит отдельным блоком как **Text-triggers**, списком по
  одной фразе на строку (последняя фраза не тащит за собой точку конца предложения).
- Аналогично для маркера «Команды:» — блок **Slash-triggers**.
- **+ Text-trigger** — добавляет новые словесные триггеры прямо в `description:` файла на диске (через
  запятую можно сразу несколько). Если секции триггеров ещё не было — создаёт её.
- **+ /trigger** — то же самое для слэш-команд, отдельная секция «Команды:».
- **Edit** у Text-triggers — разворачивает список с крестиком у каждой фразы; удаление фразы сразу
  пишется в файл. Если удалить последнюю фразу — вся секция «Триггеры:» убирается из описания целиком,
  а не остаётся пустой.
- **Delete Skill** (правый верхний угол попапа) — с подтверждением («Delete? / Confirm / Cancel»)
  архивирует весь скилл: перемещает его папку целиком (включая вспомогательные файлы) в
  `~/.claude/skills/_archive/skills-retired-<сегодняшняя-дата>/`. Не удаляет безвозвратно.

## Общее

- Иконка в мунбаре: сине-фиолетовый градиент, глиф `chart.bar.fill` из SF Symbols.
- Автозапуск при логине через LaunchAgent (`~/Library/LaunchAgents/brain.kirill.skilloptimizer.plist`).
- Во время скана транскриптов (первый запуск после установки/перезапуска) футер показывает анимированное
  «Indexing skills…» (три точки, пульсируют по очереди) вместо «Updated:» — интерфейс на это время
  схлопывается на одну строку короче.
- «Updated: HH:mm:ss» и иконка рефреша рядом — кликабельны вместе, запускают ручной пересчёт.
- «⌘Q Quit» — с настоящим системным хоткеем.
- Тонкий кастомный скроллбар (наименьший системный `.mini` размер).
- **Pin mode** — иконка-булавка в футере слева от «⌘Q». Один тоггл: открепляет попап от транзиентного
  жизненного цикла мунбара и превращает его в настоящее плавающее окно (`NSPanel`, `.floating`, видно
  поверх других окон и на всех Spaces), позиционируется у правого края экрана под строкой меню. Повторный
  клик по иконке в мунбаре, пока запиновано, не открывает второй попап — поднимает уже открытую панель.
  Клик по булавке внутри панели (или Esc) — открепляет обратно, возвращает обычное поведение. Состояние
  не сохраняется между запусками — всегда стартует откреплённым. Спека: `pin_mode_spec.md`.
