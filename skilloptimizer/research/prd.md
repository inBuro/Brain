# PRD — Skill Optimizer v1.0

> По `directive_prd_notion.md`. Собран из `brief.md`, `competitive_analysis_final.md`, `audit/audit_report.md`,
> `personas.md`, `interview_*.md` (три штуки), `features_list.md`, `prioritization.md`, `mvp_scope.md`.

## 1. Executive Summary

Skill Optimizer — menu bar утилита для macOS, которая показывает плотность реального использования Claude Code
skills и позволяет чистить/дорабатывать их прямо из попапа, без похода в редактор кода.

**Проблема:** у power-users Claude Code библиотеки кастомных скиллов разрастаются (десятки+ файлов), и не
существует способа увидеть, какие из них реально используются, а какие превратились в мёртвый груз, раздувающий
стартовый контекст сессии («Skill Bloat» — ключевая, широко обсуждаемая боль сообщества, см.
`deep_research_results.md` §2 и §7).

**Ключевой инсайт исследования:** ниша content-level анализа эффективности AI-инструкций свободна — конкуренты
в соседних категориях (AI usage/observability, menu bar time tracking, prompt/LLM-ops observability, dead-code
detection) закрывают время/токены/деньги или application-промпты, но ни один не анализирует содержание и
триггеры ambient-инструкций конкретного coding-агента и не даёт править их прямо из UI с откатом
(`competitive_analysis_final.md`, Executive summary).

**Решение:** см. `mvp_scope.md` — наблюдение (3 таймфрейма, сортировка) + диагностика (триггеры скилла) +
правка (добавление/удаление триггеров прямо в файл) + чистка (архивация с откатом), полностью локально.

**Primary-персона и её JTBD:** «Архитектор библиотеки» — понять, какие скиллы реально живые, и почистить
мёртвый груз; вторая грань той же аудитории — «Точечный доработчик триггеров» — за 10 секунд посреди работы
дописать триггер, который не сработал.

## 2. Цели и метрики

> Рабочая гипотеза — продукт впервые выходит за пределы одного пользователя, исторических данных о конверсии/
> retention нет (см. открытый вопрос в brief.md §6). OKR ниже составлены под релиз v1.0, не подтверждены живыми
> данными.

**O1 — v1.0 становится реальным ежедневным инструментом для новых пользователей, не только для автора.**
- KR: N установок через Homebrew в первый месяц после публикации (N зависит от канала анонса — Show HN/r/ClaudeCode, не зафиксировано)
- KR: ≥50% установивших сохраняют активный LaunchAgent (не удалили приложение) через 30 дней
- KR: ≥30% пользователей выполняют хотя бы одно действие правки/архивации (не только просмотр) в первый месяц — прямой индикатор, что продукт используется на всю глубину, не как игрушка

**O2 — подтвердить готовность платить за paid-действия (freemium-гипотеза из ресёрча).**
- KR: конверсия free→paid ≥ порога, который делает Setapp/One-time экономику жизнеспособной (точный порог — задача ценообразования, не этого документа)
- KR: ноль обращений/жалоб на порчу `SKILL.md` через paid-функции редактирования — учитывая, что находки аудита №2 и №5 напрямую связаны с готовностью платить (интервью library_architect)

**North Star:** количество content-level действий (правка триггера + архивация) на активного пользователя в
неделю — отличает продукт от конкурентов, которые меряют только время/токены/лимиты, и напрямую отражает
JTBD, а не просто открытие попапа.

## 3. Целевая аудитория

- **«Архитектор библиотеки» (primary).** Опытный power-user с 30+ скиллами, роутеры+подскиллы. JTBD: понять,
  что мёртвый груз, и почистить. Ревизует раз в 1-2 недели целенаправленно.
- **«Точечный доработчик триггеров» (primary, вторая грань той же аудитории).** Тот же профиль в реактивном
  режиме — посреди работы чинит один не сработавший триггер за секунды, не открывая редактор кода.
- **«Нетехнический power-user Claude Code» (secondary).** Определяет потолок публичной аудитории — использует
  Claude Code активно, но не знает терминов skill/trigger/SKILL.md. Не входит в MVP-скоуп (см. `mvp_scope.md`,
  «что не входит»), но формирует v1.1-требования (человекочитаемые подписи, интерпретация чисел).

## 4. Конкурентный ландшафт

Восемь исследованных продуктов в четырёх категориях (AI usage/observability, menu bar productivity,
prompt/LLM-ops, dead-code detection) закрывают соседние ниши, но ни один не соединяет: ambient-инструкции
конкретного AI-ассистента + content-level видимость + safe-действие из UI с откатом.

| Конкурент | Ближе всего по | Чего не хватает по сравнению с нами |
|---|---|---|
| AgentPeek | Форм-фактору (menu bar/notch) | Только токены/статус сессий, без содержания скиллов |
| Knip | Механике (report→act) | Нет GUI, нет архивации с откатом |
| PromptLayer | Content-layer редактированию | Только application-промпты через SDK, не ambient-инструкции агента |
| WakaTime | Зрелости AI-дашборда | Аналитика времени/токенов, не содержания SKILL.md |

Три фичи плана не встречаются одновременно ни у одного конкурента: просмотр содержательных триггеров,
редактирование конфигурации прямо из UI, архивация с возможностью отката (`competitive_analysis_final.md`).

## 5. MVP Scope

См. `mvp_scope.md` полностью. Кратко: всё уже реализованное (наблюдение/диагностика/правка/архивация) плюс
три Major-фикса из аудита (видимое «Saved», undo на удаление триггера, приглушённый счётчик роутера), плюс
in-app онбординг про приватность, плюс решение о монетизации (free=просмотр/paid=действия, разовая покупка),
плюс дистрибуция через Homebrew (без App Store в этой версии).

## 6. User Stories

**US-1.** Как «Архитектор библиотеки», я хочу видеть список скиллов, отсортированный по активности за неделю,
чтобы быстро найти кандидатов на архивацию.
- AC: список загружается без пересканирования диска при повторном открытии в течение сессии
- AC: сортировка переключается мгновенно между «321» и «ABC»
- Приоритет: Must (уже реализовано)

**US-2.** Как «Точечный доработчик триггеров», я хочу видеть чёткое подтверждение, что мой новый триггер
сохранился, чтобы не сомневаться и не открывать файл в редакторе для проверки.
- AC: после `+ Text-trigger` показывается видимое сообщение об успехе не менее ~1 секунды, а не мгновенно
  схлопывающееся поле
- AC: фраза видна в списке Text-triggers сразу после сохранения, без необходимости заново открывать попап
- Приоритет: Must (фикс аудит #5) — **закрыто 2026-08-30**, см. `docs/fixes_pending.md`

**US-3.** Как «Точечный доработчик триггеров», я хочу подтверждение или возможность отменить удаление
триггера, чтобы случайный клик по крестику не стоил мне формулировки, которую я подбирал долго.
- AC: удаление фразы либо запрашивает подтверждение, либо даёт undo в течение нескольких секунд после клика
- AC: поведение согласуется с уже существующим двухшаговым подтверждением Delete Skill
- Приоритет: Must (фикс аудит #2) — **закрыто 2026-08-30**, см. `docs/fixes_pending.md`

~~**US-4.** Как «Архитектор библиотеки», я хочу видеть приглушённый счётчик у роутера без собственных прямых
вызовов, чтобы понимать порядок списка без разворачивания каждой группы.~~
**Отклонено владельцем 2026-08-30** — счётчик признан ненужным, снято из скоупа целиком (было Must, фикс
аудит #4).

**US-5.** Как новый пользователь любого профиля, я хочу при первом запуске понять, что делает приложение и
что мои данные не покидают компьютер, чтобы решить, доверять ли ему доступ к моим файлам.
- AC: при первом запуске (или через `?`-попап) показывается короткое объяснение назначения и privacy-модели
- AC: текст не использует термин «плотность скиллов» без пояснения — говорит языком результата
- Приоритет: Must (аудит #6, table stakes для публичного релиза)

**US-6.** Как владелец продукта, я хочу, чтобы просмотр списка был бесплатным, а правка/архивация — платной
разовой покупкой, чтобы монетизировать продукт без модели подписки, которую отвергает целевая аудитория.
- AC: free-тир полностью функционален для сценария наблюдения и диагностики
- AC: paid-разблокировка — одна покупка, не подписка
- Приоритет: Must (решение монетизации, подтверждено дважды в интервью)

## 7. Нефункциональные требования

- **Платформа:** macOS 13+ (SwiftUI `MenuBarExtra`).
- **Производительность:** холодный скан ~20-30 сек CPU на корпусе ~1.8 ГБ транскриптов; последующие сканы
  почти бесплатны благодаря кэшу по mtime. Нужно понять, как деградирует на корпусах в разы больше — не
  протестировано.
- **Приватность:** 100% Local-First, ноль сетевых вызовов, ноль телеметрии — ключевой дифференциатор, должен
  оставаться архитектурным инвариантом, не только маркетинговым тезисом.
- **Дистрибуция v1.0:** Homebrew, ad-hoc codesign (не notarized). App Store — вне скоупа этой версии, требует
  отдельного архитектурного решения по sandbox.
- **Формат данных:** парсинг `.jsonl`-транскриптов Claude Code — формат не задокументирован публично Anthropic,
  необходима модульная архитектура парсера (Adapter Pattern), чтобы обновление Claude Code не ломало продукт
  без возможности быстрого патча.

## 8. Риски и открытые вопросы

- **Риск формата данных.** Изменение структуры `.jsonl`-логов Claude Code — средний риск, митигация — Adapter
  Pattern + авто-апдейт (`deep_research_results.md`, таблица рисков).
- **Live-session staleness — закрыто задним числом 2026-08-29, ответ «да, устаревает».** `deep_research_results.md`
  §1 (таблица уровней расширения) уже документирует механизм: описание скилла (включая триггеры) грузится
  «в стартовом контексте», полное тело — только «при активации». Это значит, что решение модели вызвать
  скилл на новую фразу опирается на снимок описаний, сделанный в начале сессии — правка `description:`
  через попап посреди уже идущей сессии **не** ретроактивно обновляет то, что модель уже «знает» о
  триггерах в этой сессии; вступает в силу только со следующей сессии. Отдельно от этого: если скилл уже
  вызван по имени явно, тело файла подгружается заново на момент вызова — так что для персоны «Точечный
  доработчик триггеров» это подтверждает именно тот страх, который она высказала в интервью: обещание
  «10 секунд без потери мысли» не выполняется для автоматического триггера, только для явного вызова по
  имени. UI-сообщение «изменения вступят в силу со следующей сессии» (US уже в `features_list.md`) теперь
  не гипотеза, а подтверждённое требование.
- **App Store vs Homebrew архитектурное противоречие.** Sandbox требования конфликтуют с прямой записью в
  `SKILL.md` — решено на уровне «оба канала», но не решено технически, как. Отложено за пределы v1.0
  (см. `mvp_scope.md`, «что не входит»).
- **Нишевость рынка.** Ниша объективно узкая — ни у одного исследованного конкурента нет проверенной бизнес-
  модели именно для этой комбинации фич (`competitive_analysis_final.md`, риск-факторы). OKR раздела 2 не
  подтверждены реальными данными, это гипотезы к первому релизу.
- **Menu bar clutter и «нет цикла возврата».** Секондари-персона рискует забыть о продукте не из-за трения в
  конкретном экране, а из-за отсутствия понятной причины открывать его регулярно (интервью
  nontechnical_poweruser) — системное ограничение канала, не решается только доработкой UI.
- **Референтная категория конкурентов не закрыта окончательно.** Расширение на prompt/LLM-ops и dead-code
  detection категории учтено в `deep_research_results.md` и `competitive_analysis_final.md`, но это
  аналитическая рамка для позиционирования команды, не готовый внешний копирайт (см. оговорку о
  позиционировании в `competitive_analysis_final.md`).

## 9. Roadmap

- **v1.0 (MVP, публичный релиз):** все Must have из `prioritization.md` — базовый набор наблюдения/
  диагностики/правки/архивации (уже есть) + 3 Major-фикса аудита + онбординг + монетизация + Homebrew.
- **v1.1:** человекочитаемые подписи поверх `router:subskill`, интерпретация чисел, массовая архивация,
  быстрый поиск/фильтр, подсказка про Pin mode, сообщение о live-session staleness (по итогам технической
  проверки), формулировка «убрать то, чем не пользуешься», кнопка «Open Skill», ручной resize панели
  (зарезервировано 2026-08-30 — уже реализовано в коде владельца, ждёт деплоя).
- **v2.0 (Could have, не обязателен к реализации):** звёздочный рейтинг + сортировка по нему, «considered
  but not fired» счётчик конфликтов триггеров, history/diff перед сохранением правки, редизайн иконки
  мунбара, смена chevron на информационную иконку.
