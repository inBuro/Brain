# Конкурентный анализ: WakaTime, AgentPeek, Rize, Timing, Faros AI

## Почему выбраны именно эти конкуренты

WakaTime и AgentPeek закрывают категорию AI-usage analytics — один как кросс-платформенный трекер кодинга с новым AI-дашбордом для Claude Code/Cursor/Copilot, второй как единственный нативный macOS menu bar app с прямым фокусом на токен-лимитах AI-агентов. Rize и Timing — ближайшие аналоги в нише «автоматический macOS menu bar трекер для разработчиков», ориентированные на дистрибуцию и паттерны UX того же сегмента, что и Skill Optimizer. Faros AI представляет enterprise-конец спектра — команды, которым нужна observability AI-инструментов в масштабе.

## WakaTime

WakaTime — ветеран трекинга кодинга (10+ лет), устанавливаемый как плагин в 50+ редакторов. В 2026 году WakaTime добавил полноценный AI-дашборд, отслеживающий Claude Code, Cursor, GitHub Copilot и другие инструменты: adoption rate, estimated spend по модели, соотношение AI-generated vs human-written кода и Human Follow-up Rate. Бесплатный тир ограничен одной неделей истории, а все AI-метрики доступны только на Premium ($12.83–14/мес). Интерфейс — веб-дашборд; нативного macOS menu bar приложения нет, что делает UX менее «тихим» и ambient по сравнению с конкурентами из menu bar ниши. Зато WakaTime предлагает самый широкий охват данных и export — пригодится командам и freelancers, которым нужна отчётность.

## AgentPeek

AgentPeek — самый прямой аналог Skill Optimizer в нише macOS menu bar + AI coding tools. Нативное приложение для Apple Silicon (macOS 14+) отслеживает токен-лимиты 22+ AI-агентов, включая Claude Code как первоклассный объект: 5-часовые и 7-дневные лимит-окна с обратными отсчётами, budget alerts, 14-дневная история с разбивкой на input/output/cache. Онбординг максимально безболезненный — никаких API-ключей, приложение читает данные прямо из системных хранилищ, которые Claude Code уже ведёт. Слабое место: ценообразование непрозрачно (only «3-day free trial» без публичных тарифов), и инструмент фокусируется на количестве токенов, но не на паттернах использования — что именно вы запускаете, насколько эффективно, что не используется.

## Rize

Rize — умный macOS + Windows productivity tracker, позиционирующий себя как «персональный тренер продуктивности». Автоматически категоризирует активность с помощью AI, отслеживает focus sessions, измеряет ежедневный focus score (0–100) и в режиме реального времени нотифицирует, если вы уходите в дистракции. Поддерживает Pomodoro, фоновую музыку для фокуса, интеграцию с календарём. Дизайн современный и хорошо читаемый, onboarding прост. Однако Rize не специализируется на разработке и не отслеживает ничего про AI-инструменты: он видит, что вы открывали VS Code или Cursor, но не что вы в них делали. Отсутствие free tier ($9.99/мес при annual billing) — барьер для trial-пользователей.

## Timing

Timing — нативный macOS time tracker с 10-летней историей, ориентированный на фрилансеров и консультантов. Полностью автоматический: никаких кнопок «начать/закончить» — приложение само строит хронологию по активным окнам, импортирует Screen Time с iPhone, детектирует звонки. В 2026 году Timing добавил AI-сводки дня и ночи. Недостатки применительно к аудитории Skill Optimizer: нет developer-специфичных фич, нет трекинга AI-инструментов, интерфейс заточен под биллинг-клиентов, а не под оптимизацию рабочего процесса разработчика. Из плюсов — цена ($7/мес), зрелость продукта и пример отличного автоматического tracking UX без навязывания ручных действий.

## Faros AI

Faros AI — enterprise-платформа для engineering intelligence, интегрирующаяся с GitHub, Jira и 100+ SDLC-инструментами. В 2026 году сфокусировалась на AI-трансформации: отслеживает ROI внедрения AI-инструментов (PR velocity, throughput, code quality, bug rate), строит token intelligence, позволяет governance-командам видеть spend по модели и по разработчику. Позиционируется для CTO и engineering directors, которым нужно ответить акционерам на вопрос «что даёт Copilot/Claude Code за $200–600/разработчика в месяц». Для индивидуального пользователя это overkill и enterprise pricing (не раскрывается, только demo). Faros AI показывает, что рынок observability AI-инструментов созрел на enterprise-уровне, но persona individual developer практически не обслуживается.

## Общие выводы

**Где ниша Skill Optimizer**

Ни один из пяти конкурентов не отвечает на вопрос «какие мои skills/инструкции реально используются, а какие мертвы». AgentPeek смотрит на токены, WakaTime — на время, Rize/Timing — на активное окно, Faros AI — на PR-метрики. Skill Optimizer занимает уникальную нишу: *контентная observability* Claude Code — не «сколько токенов», а «какие инструкции работают, какие не срабатывают, и что можно безболезненно убрать». Это прямая аналогия с «dead code detection», но для instruction layer.

**В чём Skill Optimizer может быть сильнее**

AgentPeek ограничен количественными метриками без качественного анализа; WakaTime даёт AI-данные только в веб (не ambient); Rize и Timing вообще не видят содержимого AI-взаимодействий. Skill Optimizer может выиграть за счёт: (1) нулевого трения при онбординге в стиле AgentPeek — читать уже существующие `.claude/` файлы без ключей; (2) ambient menu bar UX в стиле Rize/Timing — данные всегда перед глазами, не требуют открывать браузер; (3) actionable инсайтов — не просто «этот скилл использовался 0 раз», а предложение «заархивировать» с одним кликом.

**Какие UX-паттерны стоит перенять и у кого**

У AgentPeek: frictionless onboarding без API-ключей и компактный popover с live-метриками — именно этот паттерн задаёт планку для Claude Code tools. У Rize: цветовое кодирование «здоровья» (зелёный/жёлтый/красный) и daily score как мотивационная абстракция — translate в «skill health score» или «active skills %». У Timing: принцип полной автоматичности без ручных действий — Skill Optimizer должен работать пассивно, не требуя от пользователя логировать запуски вручную. У WakaTime: разбивка «AI-generated vs human-written» как паттерн сравнения двух режимов работы — применительно к Skill Optimizer это может выглядеть как «triggered автоматически vs вызван вручную».

## Расширение (2026-08-29): Prompt/LLM-ops и dead-code detection

По прямому запросу владельца скоуп расширен на две категории, которых не было в первом заходе.

### Почему именно эти продукты

Для категории **Prompt/LLM-ops** выбраны Langfuse и PromptLayer: оба работают с «инструкционным слоем» LLM-приложений — хранят, версионируют и отслеживают, какие промпты живые и эффективные. Это ближайшая по логике параллель к тому, что делает Skill Optimizer, только на уровне приложения, а не инструментального окружения ассистента. Для категории **dead code detection** выбран Knip как де-факто стандарт 2026 года в JS/TS-экосистеме — он решает буквально ту же задачу, что Skill Optimizer, только для файлов и экспортов, а не для instruction-файлов.

### Профили продуктов

**Langfuse** — самый популярный open-source инструмент LLM-observability, недавно приобретён ClickHouse. Ключевая для аналогии фича — Prompt Registry: промпты живут в централизованном хранилище, версионируются автоматически, деплоятся через метки, и runtime-приложение подтягивает нужную версию по имени и метке. Архитектурно очень близко к тому, как работают Claude Code skills — именованные, версионируемые инструкции, подтягиваемые по ситуации. Принципиальное отличие: Langfuse видит только то, что прошло через явный SDK-вызов — он «слеп» к тому, какие инструкции вообще существуют в окружении, если они не обёрнуты в LLM-вызов.

**PromptLayer** — специализируется на промпт-менеджменте, выделяется поддержкой нетехнических редакторов (PM, предметные эксперты правят промпты в UI наравне с инженерами) — прямая параллель к задаче Skill Optimizer дать пользователю редактировать trigger-фразы прямо из интерфейса. В 2025–2026 рынок консолидировался: Humanloop закрылся, Helicone куплен Mintlify и переведён в режим обслуживания, PromptHub закрылся — PromptLayer остаётся одним из устойчивых игроков сегмента.

**Knip** — стандарт de facto для обнаружения мёртвого кода в JS/TS проектах 2026 года (40M скачиваний/мес, используется Adobe, Shopify, Microsoft, Vercel). UX-механика: по умолчанию только репортит (`npx knip`), с флагом `--fix` применяет исправления инкрементально, всегда рекомендует review git diff перед коммитом. Нет GUI, нет понятия «архивировать» — только «удалить», что и есть ключевое отличие от Skill Optimizer, где архивирование (перенос на диск без уничтожения) — центральная операция.

### Общие выводы (расширение)

Две новые категории **усиливают и уточняют** ранее сформулированную нишу Skill Optimizer как «dead code detection для инструкционного слоя».

**Аналогия с dead-code инструментами оказывается значительно точнее**, чем с AI-usage analytics (WakaTime, AgentPeek). Knip решает буквально ту же задачу: найти артефакты, которые существуют в проекте, но никогда не задействуются → показать пользователю → дать действовать напрямую. Skill Optimizer делает то же самое для skill-файлов. Разница — в объекте анализа (instruction files vs code exports/deps) и в том, что Skill Optimizer добавляет in-UI редактирование — Knip только репортит и авто-фиксит, но не даёт интерактивно менять содержимое найденных артефактов.

**В LLM-ops пространстве** (Langfuse, PromptLayer) нет ни одного инструмента, который делает то, что делает Skill Optimizer: отслеживает, какие конкретные instruction/skill-файлы в окружении ассистента вообще когда-либо срабатывали, какие из них «мёртвые», и позволяет редактировать их trigger-условия прямо из UI. Оба работают на уровне application-prompts (то, что разработчик явно передаёт в SDK), а не на уровне ambient instructions ассистента. Слой между «observability LLM-приложения» и «dead code в кодовой базе» остаётся незакрытым — это и есть точное место Skill Optimizer на карте рынка.
