# Scope MVP (v1.0 публичного релиза) — Skill Optimizer

> По `directive_scope_prioritization.md`, шаг 3. «MVP» здесь — не первая версия личного инструмента (он уже
> существует и используется), а минимальный публичный релиз: то, что нужно доработать/починить поверх уже
> реализованного, прежде чем показать продукт кому-то, кроме владельца.

## Одно предложение

Menu bar утилита для macOS, которая честно и без трения показывает, какие Claude Code skills реально
используются, а какие — мёртвый груз, и позволяет за секунды почистить триггеры и заархивировать
неиспользуемое прямо из попапа, не открывая редактор кода и не отправляя ничего с компьютера пользователя.

## Список фич MVP (только Must have)

**Уже реализовано (см. `docs/features.md`):**
- Сканирование `~/.claude/projects/**/*.jsonl` + кэш по mtime
- 3 таймфрейма (24ч/неделя/месяц), сортировка активность/алфавит, группировка роутер→подскиллы
- Попап описания скилла с Text-triggers/Slash-triggers
- `+ Text-trigger` / `+ /trigger`, Edit/удаление фразы
- Delete Skill = архивация с подтверждением, реверсивно
- Acknowledge свежей активности (`+N`)

## Основной сценарий (primary-персона «Архитектор библиотеки»)

1. Открывает мунбар → видит список скиллов, отсортированный по активности за неделю.
2. Замечает скилл в самом низу с нулевым счётчиком за месяц.
3. Кликает на него → видит его текущие триггеры, убеждается, что действительно не пользуется.
4. Delete Skill → подтверждает → скилл уезжает в `_archive/`, не теряется безвозвратно.
5. Возвращается через неделю, повторяет — без сюрпризов, без испорченных файлов.

Вторая грань того же основного сценария (persona «Точечный доработчик триггеров»): посреди работы замечает,
что скилл не сработал на ожидаемую фразу → открывает попап → дописывает триггер → видит явное подтверждение,
что фраза сохранилась → продолжает работу без потери мысли.

## Что осознанно НЕ входит (топ-3 из Should have)

1. **Человекочитаемые подписи поверх `router:subskill` и интерпретация чисел** — обе фичи закрывают потолок
   аудитории (secondary-персона «Нетехнический power-user»), но primary-аудитория MVP — уже опытные power-users,
   которые сами придумали эти имена. Откладываем до v1.1, когда/если решение расширяться на менее техническую
   аудиторию будет принято отдельно.
2. **Массовая архивация нескольких скиллов разом** — удобство для регулярной ревизии, но основной сценарий
   работает и по одному клику; не блокирует первый релиз, добавляем следующим по частоте использования.
3. **App Store билд** — архитектурно конфликтует с прямой записью в `SKILL.md` (нужен sandbox-exempt доступ),
   требует отдельного решения, какие фичи урезать под sandbox. Не блокируем релиз через Homebrew ожиданием
   этого решения — оба канала как «Решено» в брифе, но не одновременно.
