# Конкурентный анализ Skill Optimizer — итоговый документ

> Основано на: brief.md, competitive_analysis.md (быстрый ресёрч — 5 конкурентов + расширение 2026-08-29 на 3 конкурента из двух дополнительных категорий: prompt/LLM-ops и dead-code detection). Deep Research (Gemini) на момент подготовки этого документа ещё не проведён — промпт готов в `deep_research_prompt.md`, ждёт ручного запуска.

## Executive summary

Skill Optimizer — личный menu bar инструмент для наблюдения и управления библиотекой Claude Code skills — не имеет прямых конкурентов в узкой формулировке «Claude Code skill density tracker». Восемь исследованных продуктов в четырёх категориях (AI usage/observability: WakaTime, AgentPeek, Faros AI; менюбар productivity: Rize, Timing; prompt/LLM-ops: Langfuse, PromptLayer; dead-code detection: Knip) закрывают соседние ниши, но ни один не соединяет все три слоя, которые есть у Skill Optimizer одновременно: ambient-инструкции конкретного AI-ассистента (не только явные SDK-вызовы, как у Langfuse/PromptLayer), content-level видимость происходящего (не только время/токены, как у WakaTime/AgentPeek/Faros), и safe-действие из UI (архивация с откатом, чего нет даже у Knip — механически ближайшего аналога, у которого есть только безвозвратное удаление через CLI). Ближе всех по форм-фактору — AgentPeek (нативный macOS menu bar, нулевое трение онбординга); ближе всех по механике — Knip (report → act, но без GUI и без архивации); ближе всех по content-layer редактированию — PromptLayer (правка нетехническим пользователем в UI, но только application-промптов). Ни один по отдельности не покрывает то, что Skill Optimizer даёт синтезом всех трёх. Главный открытый риск — не конкурентный, а стратегический: публичный релиз одобрен условно (если ресёрч подтвердит спрос), канал — App Store и Homebrew одновременно, что создаёт нерешённое архитектурное противоречие (sandbox App Store vs прямая запись в файлы).

## Оговорка о позиционировании

> Добавлено 2026-08-29 по прямому замечанию владельца.

Формулировка «dead code detection для instruction layer» — это **аналитическая рамка для нас** (чтобы понять место на рынке, найти аналоги вроде Knip, позаимствовать UX-паттерны типа safe report→fix). Это **не рекомендация для внешнего позиционирования**. Значительная часть реальной аудитории Skill Optimizer не знает и не обязана знать, что такое dead-code-detection тулы — это developer-tooling жаргон. Даже среди power-users Claude Code есть те, кто не хочет лезть в код, не разбирается в устройстве LLM и избегает текстовых редакторов (см. персоны в brief.md — не все три роли одинаково технические). Внешний копирайт (лендинг, App Store листинг, README) должен вести с языком результата — «увидь, что из твоих команд реально используется», «почисти библиотеку скиллов одним кликом» — а не с категорией инструмента. Ниша из ресёрча не выбрасывается, но не должна становиться первой фразой на лендинге; конкретные формулировки — отдельная задача копирайтера, не решается в этом документе.

## Таблица фич

См. полную версию в `competitor_features.md`. Три фичи плана Skill Optimizer не встречаются одновременно ни у одного из восьми конкурентов: просмотр содержательных триггеров конкретного элемента, редактирование конфигурации прямо из UI (без похода в файл/код), архивация неиспользуемого элемента с возможностью отката.

## SWOT — краткая версия

| Конкурент | Strength | Weakness | Opportunity (для нас) | Threat (для нас) |
|---|---|---|---|---|
| WakaTime | 10+ лет данных, AI-дашборд для Claude Code | Нет menu bar, AI-фичи только платно | Смотрит на время/объём, не на содержание | Может углубиться в анализ инструкций |
| AgentPeek | Прямой аналог по форм-фактору, нулевое трение | Только токены, без содержания | Соседняя полка, не прямое столкновение | Может расшириться на «что вызывалось» |
| Rize | Сильный мотивационный UX (score, цвет) | Не developer/AI-специфичен | Паттерн скоринга можно позаимствовать | Минимальная — разная аудитория |
| Timing | Полная автоматичность, зрелость | Нет AI/dev-фич вообще | Подтверждает стандарт «без ручных таймеров» | Минимальная |
| Faros AI | Глубокая enterprise-аналитика AI ROI | Enterprise-цена, overkill для одного юзера | Валидирует нишу «AI observability» в целом | Нет, если не выпустят lite-версию |
| Langfuse | Prompt Registry — архитектурно близкий паттерн | Видит только явные SDK-вызовы, не ambient-инструкции | Идею версионирования триггеров можно позаимствовать | Минимальная — разный слой стека |
| PromptLayer | In-UI редактирование нетехническим пользователем | Только application-промпты, требует SDK | Валидирует спрос именно на эту фичу Skill Optimizer | Минимальная — целится в команды, не в power-users |
| Knip | Механически ближайший аналог (report→fix), 40M скачиваний/мес | Нет GUI, нет архивации — только удаление | Доказывает спрос на «dead code detection» в соседнем домене | Практически нулевая — разные домены |

## UX-паттерны: стандарт и рекомендации

**Рыночный стандарт:** полная автоматичность сбора данных, разбивка по день/неделя/месяц, компактный menu bar popover как основной UI, freemium/trial как модель входа.

**Взять и у кого:** нулевое трение онбординга без ключей (AgentPeek), философия «никаких ручных таймеров» (Timing, уже реализовано), лёгкая мотивационная метрика поверх сырых чисел (Rize — цвет/score), сопоставление двух режимов использования как формат инсайта (WakaTime — AI vs human → у нас: авто-триггер vs слэш-команда), safe-by-default цикл report-only → явный `--fix` (Knip), history/diff перед сохранением правки (PromptLayer). Полный разбор — `competitor_ux_patterns.md`.

## Ключевые дифференциаторы и risk factors

**Дифференциаторы:**
- Единственный инструмент, показывающий содержательное использование конкретных AI-инструкций уровня ambient-окружения ассистента (не application-промптов и не агрегированного времени/токенов).
- Единственный с прямым редактированием конфигурации (триггеров) из UI без похода в файл.
- Единственный с архивацией (перенос с возможностью отката), а не безвозвратным удалением — даже у Knip, ближайшего механического аналога, этого нет.
- Полностью локальный, без облака, без API-ключей, без телеметрии, без SDK-интеграции — сильнее по приватности и трению онбординга, чем любой из восьми конкурентов.

**Риск-факторы:**
- Формат данных Claude Code (`~/.claude/projects/**/*.jsonl`) не документирован публично Anthropic — при публичном релизе это системный риск хрупкости, которого нет у конкурентов, работающих через официальные API/SDK/плагины.
- Ниша объективно очень узкая (только пользователи Claude Code с кастомной библиотекой skills) — при публичном релизе потребует явного ответа на вопрос размера рынка, которого сейчас нет (см. Deep Research prompt, вопрос 1).
- Двойной канал дистрибуции (App Store + Homebrew) создаёт нерешённое архитектурное противоречие: App Store требует sandbox, конфликтующий с ключевой фичей записи в файлы вне sandbox; вероятное решение — разные уровни фич по каналу, но это отдельная задача вне текущего ресёрча.
- Ни один из исследованных конкурентов не решает задачу Skill Optimizer целиком — это одновременно сила (пустая ниша) и риск (нет проверенной бизнес-модели именно для этой комбинации фич; ближайший по духу Knip монетизации не имеет вообще, а PromptLayer/Langfuse монетизируются на команды, не на индивидуальных пользователей).
