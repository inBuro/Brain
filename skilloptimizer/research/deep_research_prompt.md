# Промпт для Gemini Deep Research

Скопируй всё, что ниже черты, в Gemini Deep Research без изменений.

---

Я проектирую **Skill Optimizer** — приложение для строки меню macOS, которое показывает плотность использования «skills» (переиспользуемых файлов-инструкций, автоматически триггерящихся по совпадению с запросом) в Claude Code, консоли для разработки на базе AI от Anthropic. Приложение читает локальные транскрипты сессий Claude Code, показывает, какие skills реально вызываются (по часам/дню/неделе/месяцу), позволяет прямо из попапа редактировать триггерные фразы конкретного skill и архивировать неиспользуемые. Сейчас это личный инструмент одного пользователя (power-user Claude Code с десятками собственных skills), без публичного релиза, без монетизации и без известных прямых конкурентов «Claude Code skill density tracker» — ближайшие аналоги (WakaTime, AgentPeek, Rize, Timing, Faros AI) закрывают только соседние ниши: тайм-трекинг, токен-лимиты AI-агентов или enterprise engineering intelligence, но ни один не смотрит на *содержательное* использование конкретных инструкций/промптов внутри AI-инструмента.

Ключевой открытый вопрос владельца продукта: имеет ли смысл когда-либо выходить за пределы личного инструмента (публичный релиз для других power-users Claude Code), и если да — через какой канал распространения и с каким позиционированием. Мне нужны данные, которых у меня самого нет и агент в моей среде разработки получить не может: динамика рынка, паттерны поведения реальных пользователей на форумах, тренды экосистемы Claude Code/AI coding tools.

Пожалуйста, исследуй следующие вопросы:

1. **Экосистема Claude Code skills/subagents/plugins в 2026 году.** Насколько активно растёт число power-users, которые пишут собственные кастомные skills (не встроенные, а личные библиотеки в духе «роутер → подскиллы»)? Есть ли статистика или качественные оценки объёма этого сообщества (GitHub-репозитории с shared skills, обсуждения на форумах/Reddit/Discord, посты в блогах Anthropic или сторонних)?

2. **Жалобы и болевые точки пользователей AI coding assistants (Claude Code, Cursor, Windsurf, GitHub Copilot) именно вокруг управления промптами/инструкциями/кастомизацией.** Что люди пишут на Reddit (r/ClaudeAI, r/cursor, r/LocalLLaMA), Hacker News, в issue-трекерах — жалуются ли на «раздутость» системного контекста, забытые/неработающие кастомные инструкции, сложность понять, что реально сработало, а что было проигнорировано моделью?

3. **Динамика рейтингов, отзывов и апдейтов у AgentPeek, WakaTime (AI-дашборд), Rize, Timing за последние 6-12 месяцев.** Растут ли они, стагнируют, меняют ли позиционирование в сторону AI-observability? Есть ли признаки, что кто-то из них уже движется в сторону «контентной» аналитики использования AI-инструментов (а не только токенов/времени)?

4. **Ценовые модели инструментов для разработчиков в нише personal productivity / AI usage analytics** — какие модели монетизации реально работают для инструмента с очень узкой нишевой аудиторией (freemium, one-time purchase, «buy me a coffee», open-source + sponsorship)? Есть ли прецеденты успешных нишевых macOS menu bar утилит для разработчиков с очень маленькой аудиторией (тысячи, а не миллионы пользователей)?

5. **Тренды в организации AI-инструкций/промпт-инжиниринге как дисциплине.** Появляются ли инструменты категории «prompt/instruction management» (версионирование промптов, A/B-тестирование системных промптов, аналитика эффективности промптов) вне контекста конкретно Claude Code — например, для команд, работающих с LLM API напрямую? Это смежная категория, из которой могут прийти паттерны или конкуренты.

6. **Политика Anthropic в отношении сторонних инструментов, читающих локальные данные Claude Code** (транскрипты сессий, файлы конфигурации `~/.claude/`). Есть ли официальная позиция, документация или прецеденты одобрения/запрета подобных сторонних утилит? Это напрямую влияет на риск для будущего публичного релиза.

7. **Reddit/форумные обсуждения именно про «skill bloat» или «context bloat»** в Claude Code и аналогах — жалобы, что слишком много кастомных инструкций/расширений замедляет или сбивает модель, и как люди сейчас вручную решают эту проблему (если решают вообще).

**Формат ответа:** структурированный отчёт по каждому из 7 пунктов отдельным разделом, с явными ссылками на источники (URL) под каждым утверждением. Там, где данных недостаточно или они противоречивы — прямо указать это, а не давать усреднённую догадку. В конце — отдельный краткий блок «Implications for Skill Optimizer»: 3-5 выводов, прямо связанных с решением о публичном релизе и позиционировании.
