# Приоритизация (MoSCoW) — Skill Optimizer

> По `directive_scope_prioritization.md`, шаг 2. Критерии Must have: (1) напрямую связана с JTBD primary-персоны,
> (2) без неё основной сценарий невозможен, (3) table stakes — есть у всех конкурентов, пользователь ждёт по
> умолчанию. Primary-персоны — «Архитектор библиотеки» и «Точечный доработчик триггеров» (см. `personas.md`,
> сводная таблица); «Нетехнический power-user» — secondary, определяет потолок аудитории, не ядро MVP.

## Must have

| Фича | Почему Must |
|---|---|
| Сканирование транскриптов + кэш по mtime | Без данных продукт не существует |
| 3 таймфрейма, сортировка активность/алфавит, группировка роутер→подскиллы | Основной сценарий наблюдения (сценарий 1 брифа) |
| Попап описания с триггерами | Основной сценарий диагностики (сценарий 2 брифа) |
| `+ Text-trigger` / `+ /trigger`, Edit/удаление фразы | Основной сценарий правки (сценарий 3 брифа) — ключевой дифференциатор продукта |
| Archive (Delete Skill) с подтверждением, реверсивно | Основной сценарий чистки (сценарий 4 брифа) |
| Acknowledge (`+N` → погасить) | Часть основного сценария наблюдения, уже часть UX-петли |
| ~~Fix: видимое «Saved» после сохранения триггера (аудит #5)~~ | **Закрыто 2026-08-30** — фикс применён, было Major, dealbreaker двух персон |
| ~~Fix: подтверждение/undo на удаление триггера (аудит #2)~~ | **Закрыто 2026-08-30** — фикс применён, тот же класс риска |
| ~~Fix: приглушённый счётчик «максимум среди детей» у роутера (аудит #4)~~ | **Отклонено владельцем 2026-08-30** — счётчик не нужен, см. Won't have ниже |
| In-app объяснение при первом запуске (что это, что данные не покидают машину) | Table stakes для публичного релиза — аудит явно помечает как «станет обязательным» |
| Модель Free (просмотр) / Paid (действия), разовая покупка | Table stakes — без решения о монетизации релиз не отгрузить; подтверждено дважды в интервью и рыночным ресёрчем |
| Дистрибуция через Homebrew (без App Store в v1.0) | App Store требует sandbox, конфликтующий с ключевой фичей прямой записи в `SKILL.md` — нерешённое архитектурное противоречие блокирует релиз через этот канал; Homebrew ограничений не имеет и уже подтверждён как предпочтение primary-персоны |

## Should have

| Фича | Почему Should, не Must |
|---|---|
| Человекочитаемые подписи поверх `router:subskill` | Критично для secondary-персоны, primary-персоны читают технические имена свободно |
| Интерпретация чисел / рекомендация действия | Та же причина — нужна для расширения аудитории, не для ядра |
| Массовая архивация нескольких скиллов | Удобство primary-персоны при регулярной ревизии, основной сценарий работает и по одному |
| Быстрый поиск/фильтр по имени | Удобство, не блокер — сейчас находит скилл прокруткой |
| Подсказка про Pin mode при первом открытии | Дешёвая доработка уже готовой фичи, не блокирует ядро |
| Сообщение «изменения вступят в силу со следующей сессии» | Факт подтверждён (`prd.md` §8, 2026-08-29), но само сообщение — UI-удобство поверх работающего ядра, не блокирует основной сценарий |
| Одна кнопка «убрать то, чем не пользуешься» (формулировка результата) | Важно для monetization-копирайта secondary-сегмента, не для функциональности ядра |
| Человекочитаемая ошибка вместо `localizedDescription` | Косметика, аудит сам не включил её в топ-таблицу |

## Could have

| Фича | Почему Could |
|---|---|
| Звёздочный рейтинг 1-5 + сортировка по нему | Подтверждена интервью как полезная для ревизионного сценария, но не для ядра; отдельная небольшая фича сама по себе |
| «Considered but not fired» — счётчик несостоявшихся срабатываний | Ценна концептуально (обе персоны вышли на неё независимо), но требует видимости внутреннего решения роутинга модели — не факт, что технически доступно; сам источник инсайта пометил её «вне текущего скоупа» |
| History/diff перед сохранением правки | Хороший паттерн (подсмотрен у PromptLayer), но не блокер и не запрошен ни одной персоной напрямую |
| Смена chevron `›` на однозначно информационную иконку (аудит #3) | Minor severity по самому аудиту |
| Более узнаваемая иконка мунбара | Помогает secondary-персоне, но конкурирует по эффекту с более дешёвым онбордингом |
