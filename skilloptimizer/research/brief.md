# Бриф: Skill Optimizer

> Собран синтезом из истории разработки продукта (не через интерактивное интервью — по прямому указанию
> владельца), поэтому структура директивы «Рекурсивный брифинг» сохранена, но раунды вопросов заменены
> прямым изложением уже известных фактов. Всё, что не подтверждено явно — вынесено в раздел 7.

## 1. Контекст продукта

Skill Optimizer — menu bar утилита для macOS, показывающая **плотность использования Claude Code скиллов**:
сколько раз и когда вызывался каждый скилл (и подскилл) из личной библиотеки пользователя, с разбивкой по
таймфреймам (24 часа / неделя / месяц) и сортировкой (по активности / по алфавиту). Данные читаются напрямую
из локальных транскриптов сессий Claude Code (`~/.claude/projects/**/*.jsonl`) — никакого облака, никакой
телеметрии наружу.

Помимо наблюдения, приложение умеет **редактировать сами скиллы прямо из попапа**: дописывать словесные
триггеры и слэш-команды в `description:` реального `SKILL.md`, удалять отдельные фразы, архивировать скилл
целиком (с возможностью отката).

Продукт родился не из рыночной гипотезы, а из личной потребности: у владельца — 9 групп-мультискиллов
(роутер → подскиллы), десятки отдельных скиллов, и не было способа увидеть, какие из них реально
используются, а какие — мёртвый груз, занимающий место в контексте роутинга.

## 2. Целевые пользователи

| Роль | Сценарий использования | Частота |
| --- | --- | ---|
| Power-user Claude Code с кастомной библиотекой скиллов (десятки+) | Хочет видеть, какие скиллы «живые», какие пылятся, чтобы чистить/дорабатывать триггеры | Ежедневно, фоново (менюбар) |
| Архитектор скиллов / «skills-architect» роль | Периодически ревизирует всю библиотеку: находит дубли, неиспользуемые скиллы-кандидаты на пенсию | Раз в 1-2 недели, целенаправленно |
| Разработчик, дорабатывающий триггерные фразы | Видит, что скилл не триггерится в ожидаемых ситуациях → добавляет фразы прямо в попапе, без похода в файл | По необходимости, реактивно |

## 3. Ключевые сценарии

1. **Фоновое наблюдение.** Иконка в мунбаре всегда под рукой; открыл — увидел, что чаще всего вызывалось за
   последние сутки/неделю/месяц.
2. **Диагностика конкретного скилла.** Кликнул на имя → увидел его текущие триггеры (словесные и слэш-команды),
   понял, почему он срабатывает или не срабатывает в нужный момент.
3. **Точечная правка триггеров.** Прямо в попапе добавил фразу или слэш-команду → они реально пишутся
   в `SKILL.md` на диске, без похода в редактор кода.
4. **Чистка библиотеки.** Нашёл скилл, которым не пользуется месяцами → архивировал одной кнопкой
   (с подтверждением), файл не потерян — уехал в `_archive/`.
5. **Подтверждение свежей активности.** Увидел зелёный `+N` у скилла (использован недавно) → кликнул,
   пометил «видел», чтобы не мозолил глаза при следующем открытии.

## 4. Технические ограничения

- **Платформа:** только macOS 13+ (SwiftUI `MenuBarExtra`, актуальная фича только с этой версии).
- **Источник данных:** локальные JSONL-транскрипты Claude Code; формат не документирован публично Anthropic —
  парсинг основан на наблюдаемой структуре, может измениться при обновлении Claude Code.
- **Объём данных:** у первого (и пока единственного) пользователя корпус транскриптов — уже ~1.8 ГБ и растёт;
  полный скан занимает ~20-30 сек CPU при холодном старте, дальше — кэш по mtime файла.
- **Запись в боевые файлы:** фичи Add trigger / Add /trigger / Delete Skill пишут напрямую в реальные
  `SKILL.md` пользователя — это одновременно ключевая ценность и главный источник риска (испортить рабочую
  библиотеку скиллов).
- **Автозапуск:** через `launchd` LaunchAgent, не через нативный macOS "Login Items" (не App Store,
  не notarized — codesign только ad-hoc).
- **Дистрибуция:** пока не рассматривалась вообще — собирается и подписывается локально на машине владельца.

## 5. UI-требования

- Один экран (попап из мунбара), без отдельных окон/настроек.
- Тёмная тема по умолчанию (белый текст на тёмном фоне), явных требований к светлой теме не было.
- Иерархия: роутеры сверху, подскиллы — с отступом под ними, без счётчика у самого роутера (если есть дети).
- Минимум хрома: убраны заголовки, где можно — текст вместо иконок (кнопки-«+», сортировка «321»/«ABC»).
- Изменение состояния (открыл Edit, добавил фразу) не должно менять размер попапа рывком.

## 6. Метрики успеха (OKR)

> Формальных OKR не формулировалось — продукт для одного пользователя, метрики neé не отслеживались.
> Ниже — рабочая гипотеза на основе того, зачем продукт строился.

- **O:** Владелец реально использует приложение как ежедневный инструмент ревизии скиллов (не забросил через неделю)
  - KR: приложение работает без падений минимум N дней автозапуска подряд
  - KR: минимум 1 скилл реально доработан (триггеры добавлены) или заархивирован через UI приложения в месяц

## 7. Открытые вопросы

> Обновлено 2026-08-29 по прямым ответам владельца.

- ~~Планируется ли выход за пределы одного пользователя~~ — **Решено:** публичный релиз планируется
  **условно** — если ресёрч покажет, что ниша пустая и на неё есть запрос. Пока это не подтверждено,
  конкурентный анализ остаётся предварительным (см. `competitive_analysis_final.md`), решение о релизе
  принимается по итогам ресёрча (в т.ч. Deep Research), а не заранее.
- ~~Канал дистрибуции~~ — **Решено:** оба сразу — Mac App Store **и** Homebrew. Здесь есть нерешённое
  техническое противоречие, требующее отдельного решения архитектуры (не блокирует ресёрч, но блокирует
  реализацию публичного релиза): App Store требует sandbox, который конфликтует с ключевой фичей прямой
  записи в `SKILL.md` вне sandbox (см. раздел 4). Homebrew ограничений sandbox не имеет. Возможный путь —
  два разных билда/уровня фич по каналу, но это отдельное архитектурное решение, не часть текущего ресёрча.
- ~~Референтная категория конкурентов~~ — **Решено (закрыто задним числом 2026-08-29):** расширение скоупа
  уже выполнено в `competitive_analysis_final.md` — итоговый набор 8 конкурентов включает обе запрошенные
  категории, **prompt/LLM-ops observability tools** (PromptLayer, Langfuse) и **dead-code/unused-dependency
  detection tools** (Knip). Этот пункт оставался помечен «открыто» по недосмотру в бухгалтерии брифа — сам
  ресёрч давно это закрыл, обновление только синхронизирует документ с уже существующим артефактом.
- ~~Нужна ли синхронизация между машинами~~ — **Решено:** не нужна, пока актуальность не возникла явно.
- ~~Стоит ли вшить «Claude»/«Cloud» в имя продукта~~ — **Решено (2026-08-30):** нет. «Cloud» технически
  неточно — приложение полностью локальное (см. раздел про источник данных, никакого облака). «Claude» в
  бренде — риск товарного знака (Anthropic не даёт сторонним продуктам заявлять аффилированность через имя).
  Use case вместо этого обозначается дескриптором **«Skill Optimizer for Claude Code»** (не часть бренда,
  не в самом названии) — например в подзаголовке/доке, а не в bundle id/executable.
