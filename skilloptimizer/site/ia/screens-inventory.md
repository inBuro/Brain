# Skill Optimizer — сайт продукта: инвентаризация секций

> По `directive_prd_to_sitemap.md`, адаптация «Лендинг» — линейная структура секций одной страницы вместо дерева.
> Источник: `research/prd.md`, `research/brief.md`, `research/personas.md`, `research/competitive_analysis_final.md`.

## Секции лендинга (из PRD)

| Секция | Что на ней происходит |
| --- | --- |
| `Hero` — герой | Название + дескриптор «Skill Optimizer for Claude Code», боль в одну строку без термина «Skill Bloat» (решение по секции `Problem`, см. `site/copy/problem-section-directions.md`), primary CTA (Install via Homebrew) |
| `Problem` — проблема | Библиотека собрана осознанно, но её работу не видно: нет прибора, который показывает, до каких скиллов Claude реально дотягивается (PRD §1, направление B — `site/copy/problem-section-directions.md`) |
| `HowItWorks` — как работает | 4 способности продукта одной цепочкой: наблюдение (3 таймфрейма) → диагностика (триггеры) → правка (add/remove прямо в файле) → чистка (архивация с откатом) (PRD §5, `mvp_scope.md`) |
| `Features` — детали фич | Карточки по тем же 4 способностям, развёрнуто: menu bar плотность, диагностика триггеров, редактирование `SKILL.md` без редактора кода, архивация с undo |
| `Privacy` — приватность | 100% Local-First, ноль сетевых вызовов, ноль телеметрии — архитектурный инвариант и ключевой дифференциатор (PRD §7), самостоятельная секция, не сноска |
| `Differentiation` — почему не Х | Позиционирование против соседних категорий (AI usage/observability, menu bar productivity, prompt/LLM-ops, dead-code detection) — ни один не соединяет content-level видимость + safe-правку с откатом (PRD §4) |
| `Pricing` — цена | Free = просмотр/диагностика, Paid = разовая покупка на правку+архивацию, не подписка (PRD §6, US-6) |
| `Install` — установка | Homebrew-инструкция, требование macOS 13+ (PRD §7) |
| `FAQ` | Вопросы вокруг приватности/формата данных/платформы — снимает возражения перед CTA |
| `Footer` | Ссылки, контакт |

## Экраны/страницы, которых в PRD нет, но без которых сайт не соберётся

> Владелец: структуру брать за образец у существующего сайта Fadercraft (`~/Projects/Projects/fadercraft`).
> Паттерн Fadercraft: одна продуктовая страница с якорными секциями (`#features`/`#support`) + отдельные
> страницы `updates.html` (changelog по продукту) и `legal.html`, общий `404.html`, футер-бренд-ссылка на `/`.
> У Skill Optimizer один продукт — мультипродуктовый навигатор (как в Fadercraft `Control XL ▾`) не нужен.

| Страница | Почему нужна | Источник паттерна |
| --- | --- | --- |
| `404` | Базовая гигиена любого публичного сайта | Fadercraft `404.html` |
| `Privacy` (отдельная страница, не только секция лендинга) | Продукт продаёт приватность как главный дифференциатор (PRD §7) — нужен разворот с деталями (что именно не собирается, как проверить) | аналог Fadercraft `legal.html`, но переименовано под смысл — приватность здесь не формальность, а продуктовый claim |
| `Updates` (changelog) | По решению владельца — держать историю версий публично, как у каждого продукта Fadercraft (`xl-updates.html`, `df-updates.html`, `sf-updates.html`) | Fadercraft `*-updates.html` |
| `Download/ThankYou` (после клика Install) | Экран подтверждения после клика — куда ведёт CTA технически (страница с Homebrew-командой или редирект на GitHub) | новое — у Fadercraft на этом месте Gumroad-checkout, здесь другая механика дистрибуции |

## Открытые вопросы

- Секция `Differentiation` — **решено:** конкурентов по имени не называем (AgentPeek/Knip/PromptLayer/WakaTime), остаёмся на уровне категорий — совпадает с оговоркой PRD §8, что референтная категория конкурентов — «аналитическая рамка для позиционирования, не готовый внешний копирайт».
- Fadercraft вдобавок держит трекнутые `*-buy.html` редиректы под каждый канал охвата (YouTube/Reddit/Telegram/Facebook) для аналитики по источнику клика. Для Skill Optimizer это имеет смысл только если планируется многоканальный аутрич уровня Fadercraft (Show HN/r/ClaudeCode и т.п.) — не решено, не блокирует v1.0 sitemap, можно добавить позже теми же руками.
- `Docs`/руководство отдельной страницей (аналог Fadercraft `guides.html`) — не заводим на v1.0: у Skill Optimizer нет сопоставимого объёма настройки (в отличие от маппинга контроллера), установка — одна Homebrew-команда.
