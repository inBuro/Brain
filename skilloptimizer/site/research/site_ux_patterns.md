# UX-паттерны конкурентных лендингов

> По `directive_competitive_analysis.md`, шаг 3, адаптация: паттерны страницы (структура, конверсия), не паттерны UI продукта (те уже в `research/competitor_ux_patterns.md`).

## 1. Рыночный стандарт — что делают все одинаково

- **Hero = заголовок + подзаголовок + primary CTA, выше сгиба, без исключений.** Все восемь без исключения.
- **Приватность адресуется хоть как-то у всех, кто вообще собирает данные.** Единственное исключение — Knip: у него нет пользовательских данных как категории (это open-source dev-tool, не runtime-агент), поэтому раздела нет — не нарушение паттерна, а его подтверждение (нет данных → нет секции).
- **Footer = склад ссылок**, не место для контента, у всех восьми.
- **Freemium/trial-заход почти универсален** среди prosumer-инструментов (Rize, Timing, частично AgentPeek) — «попробуй, потом плати» — расходится только на enterprise-полюсе (Faros — demo-only) и open-source полюсе (Knip — просто бесплатно).

## 2. Точки расхождения — где решают по-разному

| Ось | Вариант A | Вариант B | Кто где |
|---|---|---|---|
| Видимость цены | Прямо на лендинге | За кликом / за демо | A: AgentPeek, Knip. B: остальные шесть |
| Язык приватности | Конкретный технический claim («не загружает код/промпты») | Язык сертификатов (SOC 2/GDPR/HIPAA) | A: AgentPeek, Rize, Timing. B: Faros, PromptLayer |
| Место changelog | Пункт главной навигации | Отдельная маркетинговая секция / блог | Nav: AgentPeek. Секция: Faros. Отсутствует: Rize, Timing, PromptLayer |
| Тип соцдоказательства | Отзывы/рейтинги/кейсы | Открытые метрики инструмента (stars, downloads, contributors) | Отзывы: Rize, Timing, Faros, PromptLayer. Метрики: Knip. Оба сразу: WakaTime |

Ось «видимость цены» и ось «язык приватности» коррелируют с сегментом, а не выбираются независимо:
consumer/prosumer Mac-утилиты (AgentPeek/Rize/Timing) тяготеют к прямоте (цена видна ИЛИ приватность конкретна,
обычно оба), enterprise-инструменты (Faros/PromptLayer) — к непрямоте (демо-гейт, язык сертификатов).
Skill Optimizer по сегменту однозначно ближе к первой группе.

## 3. Рекомендации — какой паттерн взять, у кого, почему

- **Цена на лендинге, не за кликом.** Взять у AgentPeek — единственный из восьми, кто структурно совпадает с
  нами по форм-фактору (Mac menu bar) И модели монетизации (разовая покупка). Подтверждает PRD §6/US-6:
  free=просмотр, paid=разовая покупка — это стоит показать явно, а не прятать.
- **Приватность — конкретный технический claim, не общая формулировка.** Взять у AgentPeek/Timing: «не
  загружает X/Y/Z» вместо «мы заботимся о вашей приватности». Для нас это переносится как «читает локальные
  `.jsonl`-транскрипты и правит `SKILL.md` на диске, ничего не отправляет по сети» — прямое отражение PRD §7
  («100% Local-First... архитектурный инвариант, не только маркетинговый тезис»), а не изобретённая фраза.
- **Changelog — в навигацию, не прятать в футер.** Взять у AgentPeek (`/log` в главном меню) — совпадает с
  решением владельца держать историю версий публично.
- **Не копировать enterprise-паттерн demo-gate/раздвоенный CTA (Faros, PromptLayer).** Это паттерн для sales-led
  воронки с человеком на том конце — у нас self-serve Homebrew-установка, один чёткий CTA (Install), не два
  конкурирующих (Book a Demo / Learn more).
- **Соцдоказательство — открытый вопрос, не решается копированием.** Ни отзывов, ни рейтингов, ни цифр
  внедрения на v1.0 нет — паттерн Knip («открытые метрики вместо отзывов») ближе по духу (мы тоже
  инструмент с прозрачной механикой), но у нас пока и метрик нет (0 установок на день релиза). Решение —
  задача следующего шага (scope-приоритизация): либо секция пропускается на v1.0 и добавляется в v1.1 по
  факту первых чисел, либо заменяется на нейтральный элемент («открытый код» / «проверь сам» вместо
  социального давления).
