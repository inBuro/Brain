# 2.3. Sitemap и user flow на FigJam через агента — 14:25

Первая боевая задача модуля: PRD → sitemap и user flow прямо на канвасе FigJam.

| Тайм-код | О чём |
| --- | --- |
| 0:00 | Директива в два этапа: текстовая сборка (инвентаризация экранов → sitemap-дерево → приоритеты → user flow в Mermaid), апрув, и только потом канвас |
| 1:52 | Почему FigJam, а не Miro: перенос контента между Miro и Figma неудобен, на бесплатном тарифе Miro почти каждое действие платное |
| 2:00 | Почему дробим: токены и контекст не бесконечны, а MCP-действия едят много токенов и времени |
| 2:45 | `screens_inventory` — все экраны из PRD с описаниями. **Оставлять на английском**: фреймы агент всё равно назовёт по-английски, и связь между текстом и канвасом сохранится |
| 3:36 | Sitemap — дерево глубиной три слоя. Глубину можно поднять в директиве, но это время, токены и риск упереться в лимит Pro |
| 4:32 | User flow в Mermaid; смотреть прямо в IDE через расширение **Mermaid Viewer** (иконка с плавником) → кнопка Preview Diagram. Если не подхватилось — перезапустить среду |
| 6:19 | **Ключевое место урока — два метода отрисовки.** `generate_diagram` заточен под FigJam, работает быстро, но **всегда создаёт новый файл**: он не умеет править существующую диаграмму или дописывать в готовый FigJam |
| 7:11 | `use_figma` работает с любым существующим файлом и рисует аккуратнее, но дольше, дороже по токенам и хуже адаптирован под диаграммы |
| 8:01 | Практическое правило: первая итерация — `generate_diagram`, доработка или важный визуал — `use_figma` |
| 8:54 | Результат: sitemap на три уровня, приоритет размечен цветом (жёлтые — менее приоритетные) |
| 10:34 | Сравнение на живом примере: тот же flow через `use_figma` вышел чище и понятнее, но агент забыл подписать ветвления — под диаграммы он адаптирован хуже |
| 11:24 | Где приглядывать за агентом: выдуманные экраны, которых нет в PRD; лишние уровни вложенности; потеря качества на очень больших sitemap — тогда дробить и собирать итеративно |
| 13:05 | Домашка: пройти текстовые фазы на своём PRD и отрисовать через `generate_diagram` sitemap или один user flow |
