# 2.4. Wireframes через MCP — 27:10

Второй шаг рельса: 3–5 экранов из sitemap → low-fi wireframes в отдельном Figma Design-файле.
Во второй половине урока — отступление про Google Stitch.

| Тайм-код | О чём |
| --- | --- |
| 0:00 | Что такое low-fi: серые прямоугольники вместо картинок, рамки с текстом вместо кнопок, системный шрифт |
| 1:00 | Почему не сразу hi-fi: застрянешь в цветах и шрифтах до того, как понял структуру. Структурные проблемы на low-fi видны за минуту |
| 1:30 | Две фазы директивы: текст (выбор экранов → размеры → разметка структуры каждого экрана) с апрувом, потом канвас |
| 3:09 | **Здесь работаем через `use_figma`**, а не `generate_diagram` как в прошлом уроке |
| 3:09 | Артефакт: агент кладёт экраны не на ту страницу примерно в 2 случаях из 10 — переносится руками за секунду |
| 4:40 | Фаза размеров: агент читает PRD (минимум 1280×720) и предлагает 1440×1024 |
| 5:00 | Фаза структуры: `wireframes/` с подробным md-описанием каждого экрана; правки на этом этапе дают заметно лучший результат |
| 5:30 | Модалки: агент спрашивает, оставить обзорный экран или дорисовать окна |
| 6:10 | **Перенос FigJam → Design просто через Ctrl+C / Ctrl+V** внутри Figma; sitemap и user flow стоит перенести в тот же файл |
| 6:40 | Агент сначала проходит Update Tools — смотрит, какие инструменты доступны, и только потом рисует |
| 7:00 | Самопроверка: делает скриншот после отрисовки, видит, что ничего не появилось, и переделывает — пока результат не станет приличным |
| 7:40 | Разбор результата: структура соответствует PRD, всё на Auto Layout, детализация низкая — как и надо |
| 9:13 | **Главный дефект агента: фиксированная высота** (иногда вообще 0) вместо hug. Правится в клик, потому что всё на Auto Layout |
| 10:44 | Почему не собрать сразу на дизайн-системе: править потом проблематично; сначала структура, потом визуал |
| 11:00 | **Синхронизация**: если правишь макет руками, скажи об этом агенту (или пришли ссылку на фрейм) — автоматически он это не увидит |
| 12:18 | Отступление про **Google Stitch**: быстрый способ получить пачку правдоподобных hi-fi экранов — показать команде направление, оттолкнуться при проработке, увидеть визуализацию сложных данных |
| 13:48 | Как готовят промпт: попросить агента собрать промпт для Stitch из контекста среды. Дизайн-систему можно подсунуть как `design.md` или ссылкой на сайт, но представлена она поверхностно — в Claude Design намного лучше |
| 15:20 | Модели Stitch: Flash быстрая и слабая, 3.1 Pro — глубокая проработка; режимы Redesign и Ideate автору бесполезны |
| 16:50 | Результат: 19 экранов за ~15 минут; собрано аккуратно, но не профессионально |
| 18:20 | **Главная слабость Stitch — несистемность**: сайдбар отличается от экрана к экрану, модалки в разной стилистике |
| 19:58 | Сильная сторона — вариации: выбрать экран, попросить 3 варианта, получить разные решения (этапность с галочками, колесо ожидания) с учётом специфики вроде подтверждений крипто-платежа |
| 23:00 | Экспорт в Figma: convert → copy → Ctrl+V. Auto Layout соблюдается не везде, иногда вместо текста иероглифы — тогда экспортировать повторно |
| 23:00 | У Stitch появился MCP — результат можно передать в Claude и сверстать прототип (четвёртый модуль) |
| 23:40 | Сводка артефактов агента: слишком детальный wireframe, Lorem Ipsum вместо контекстных текстов (не должно быть, директива это запрещает), поломанный Auto Layout, несовпадение формата экрана |
| 24:30 | Приём: экраны создаются последовательно — можно смотреть в Figma по ходу и остановить агента, не сжигая токены |
