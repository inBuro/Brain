# 4.8. Дашборд юзер-тестов — 13:34

Готовый дашборд отдаётся архивом, к проекту его подключает директива `dashboard`.

| Тайм-код | О чём |
| --- | --- |
| 0:00 | **Главная мысль урока: аналитика — часть кода.** Трекер встраивается в прототип, хостинг пересобирает живую версию, она считает поведение |
| 0:40 | Отсюда порядок: метрики снимаются только после деплоя — без живой ссылки тестировать не на чем |
| 1:00 | Почему кастомный дашборд, а не Amplitude. **Первое**: сигналы трения считаются из чистых событий — маршрута и кликов, без записи экрана и личных данных |
| 1:31 | **Второе, главное — он замыкает цикл.** Большие инструменты показывают проблему и на этом всё; здесь находка превращается в задачу агенту, ты правишь, передеплоиваешь и сразу видишь, помогло ли |
| 2:00 | **Третье**: он живёт в твоей среде и знает твои гипотезы и сценарии — агент сам его дорабатывает |
| 2:20 | Честная рамка: это не замена продуктовой аналитике на миллионах пользователей, а инструмент дизайнера под быстрый тест прототипа |
| 2:40 | **Почему сбор живёт на своём сервере**: приём и хранение событий — это бэкенд, нужен всегда включённый сервер с диском. Vercel раздаёт статику и постоянный файл там не живёт |
| 3:03 | Правило: прототип может быть где угодно, данные — всегда на своём сервере |
| 3:20 | **Два пути.** Прототип на своём сервере — всё по http на одной машине, ничего не нужно |
| 3:30 | Прототип на Vercel — страница по https, а браузер блокирует запросы на http-сервер (mixed content). Обход — туннель **ngrok**, который даёт сборщику https-адрес |
| 4:33 | Установка: распаковать архив и положить папку `dashboard/` в корень среды **через файловое хранилище**, не перетаскиванием целой папки в редактор — иначе собьётся среда |
| 5:00 | Что запросит директива на пути Vercel: authtoken из ngrok, домен оттуда же и доступы к серверу (IP, root, пароль) |
| 5:10 | **Практическая ловушка**: если GitHub привязан к российской почте, регистрация в ngrok через GitHub не пройдёт — заходить через Gmail |
| 6:04 | Возможен притирочный раунд: не ко всем элементам прототипа трекер подвяжется с первого раза |
| 6:20 | **Важно про ожидание деплоя**: агент иногда делает вид, что ждёт. Проверять статус на Vercel самому — должно быть «обновлено минуту назад», статус ready; ошибки скринить агенту |
| 7:00 | **Дашборд, страница обзора**: раунды, респонденты, сценарии, статус гипотез |
| 7:35 | **Гипотезы**: формулируются с агентом и добавляются в дашборд; у каждой целевая метрика и график |
| 8:20 | Разбор сессий: что делал человек, сколько времени занял шаг, **rage-клик** (долбит в одно место), **разворот** (ушёл вперёд и вернулся) |
| 8:50 | Показатель трения показывает, насколько флоу требует внимания. При трёх респондентах вывод не делается — статус «нужен ещё тест» |
| 9:10 | **Сценарии** — те же user flow. Запускаются по входу (любой заход) или **по метке** — отдельная ссылка на сценарий, чтобы сегментировать тесты |
| 9:40 | Сводка сценария: доходимость до цели, время до цели, потерянность, воронка по экранам с крупнейшим отвалом |
| 10:20 | **Здоровье экранов**: трение, среднее время, первый клик — прозрачно ли целевое действие |
| 10:41 | **Сессии**: фильтр по сценарию, устройству и ключевой проблеме (заблудился, фрустрирован, не дошёл) |
