# 1.4. Конкурентный анализ — 8:29

Сырые ресёрчи → документ, который можно показать клиенту. Одна директива, четыре шага, четыре файла.

| Тайм-код | О чём |
| --- | --- |
| 0:45 | Директиву просто перетаскивают в чат — агент сам понимает, что делать |
| 1:00 | **Важно про имена файлов**: директива ждёт `brief.md`, `competitive_analysis.md`, `deep_research_results.md`. Файл глубокого исследования нужно переименовать точно так же, иначе агент его не подхватит |
| 1:36 | SWOT: S и W — про сам конкурент, O и T — что это значит для нас. Агент смотрит через призму нашего брифа |
| 2:25 | Как читать weaknesses: повторяющаяся слабость у нескольких конкурентов = системная проблема рынка, закроешь её — сильный аргумент |
| 2:40 | Threats формулируются как «если конкурент X добавит фичу Y, он закроет нашу нишу» — анализ про движение рынка, не только про текущее состояние |
| 3:11 | Правки вносить через агента, не руками в `.md`: иначе изменение не разойдётся по смежным файлам |
| 3:30 | Таблица фич: строки — фичи, колонки — конкуренты и мы; ✅ / ⚠️ / ❌ |
| 4:04 | Главное в таблице — строка, где у всех ❌, а у нас ✅. Это дифференциатор. Нет такой строки — тоже результат: дифференциация не в фичах, а в UX, цене, интеграциях, аудитории |
| 4:30 | Строка, где ✅ у всех — table stakes, минимум для восприятия всерьёз. ❌ напротив такой строки — проблема |
| 4:52 | UX-паттерны: рыночный стандарт («гравитация», спорить можно, но осознанно), точки расхождения, рекомендации |
| 5:37 | Пример анти-рекомендации: пошаговый визард создания сервера у TimeWeb избыточен для частника с 1–3 серверами |
| 6:25 | Финальный документ: executive summary, риски (пример — приём крипты в РФ запрещён, нужно юрлицо в ОАЭ/Гонконге), таблица фич, UX-рекомендации, выводы |
