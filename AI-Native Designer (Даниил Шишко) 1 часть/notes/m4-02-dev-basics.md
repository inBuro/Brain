# 4.2. Основа разработки — 8:17

Минимум терминологии, чтобы понимать происходящее и говорить с разработкой на одном языке.

| Тайм-код | О чём |
| --- | --- |
| 0:00 | **Три типа продуктов.** Сайт или лендинг — показать и рассказать, логики мало |
| 0:40 | Веб-приложение — интерфейс с логикой в браузере: состояние, данные, действия. Человек не читает, а работает |
| 1:00 | Мобильное приложение — камера, пуши, магазины; самый сложный тип |
| 1:14 | **Стек**: фронтенд — то, что видит пользователь; бэкенд — серверная логика и база данных |
| 2:00 | **Для прототипа и тестов нужен только фронт.** Полноценный сервис потребует бэка, но его агент тоже закроет |
| 2:27 | **Фреймворк** — каркас для фронта (React, Vue, Next.js) |
| 2:40 | Аналогия с Figma: HTML — структура слоёв, CSS — покраска и размеры, JS — прототип и логика «если нажал А, произойдёт Б» |
| 3:37 | React мыслит компонентами с вариациями — то же самое, что компоненты в Figma, только в коде |
| 3:50 | **Библиотека** — готовый кусок кода под конкретную задачу; подключаешь и настраиваешь параметры вместо написания с нуля |
| 4:50 | Соответствие типов и стеков: сайт — статика или простой фреймворк; веб-приложение — React или Next.js; мобильное — native (Swift, Kotlin) или кроссплатформа (React Native, Flutter, Expo) |
| 5:30 | **Почему React**: мышление переносится из Figma почти один в один, связать дизайн с кодом проще, и оттуда же дорога в мобильное через React Native |
| 6:00 | **GitHub** — место, где лежит код: совместная работа, история изменений. Проект = репозиторий, передать работу часто значит дать ссылку на него |
| 7:00 | Что можно отдать разработке: живую ссылку на прототип, код, каталог компонентов |
| 7:10 | **Правильный вопрос разработчикам**: на каком стеке работаете и в каком формате удобно принять. Идеально — попросить доступ к их GitHub, тогда агент сам поймёт стек и пойдёт по этим рельсам |
| 7:30 | Как открывают прототип: веб — просто ссылка; мобильный — симулятор на компьютере или приложение Expo Go на телефоне |
| 8:00 | Домашка: написать свой тип продукта и что будешь использовать |
