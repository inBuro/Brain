# 1.6. Синтетические персоны — 8:00

Прото-персоны на вторичных данных (бриф, конкурентный анализ, аудит) вместо «Анна, 32, любит йогу».

| Тайм-код | О чём |
| --- | --- |
| 0:00 | Антипример шаблонной персоны: фото из фотостока, интересы, ни на что не влияющие, цель, подходящая любому продукту |
| 0:50 | Тест полезности: помогает ли персона выбрать между двумя вариантами навигации. «Ведёт 4 кампании, переключается 15 раз в день, бесит больше двух кликов» → навигация плоская, статусы на первом экране |
| 1:15 | Почему «прото»: это гипотезы на вторичных данных, сильные и обоснованные, но требующие валидации на живых людях |
| 1:38 | Шесть блоков: роль и контекст, JTBD, паттерны поведения, раздражители, триггер выбора, инсайты |
| 1:50 | JTBD — не кто пользователь, а какую работу он нанимает продукт выполнять |
| 2:10 | Раздражители агент подтягивает из конкурентного анализа и аудита — привязывает слабые места конкурентов к конкретному человеку |
| 2:25 | Инсайты — ключевой блок, ради него всё; персона без конкретных решений бесполезна |
| 3:10 | Демо: Антон-фрилансер — «поднять сервер и не думать о нём», отсюда идея телеграм-уведомлений мониторинга |
| 4:40 | Триггер выбора: две важные строки — «что заставит остаться» (обязательное) и «дилбрейкер» (красная линия) |
| 5:25 | Сводная таблица в конце: JTBD, приоритет, ключевой дизайн-вывод по каждой персоне |
| 5:40 | Приоритизация: одна персона — primary, её потребности идут в MVP; финальное решение за вами, не за агентом |
| 6:10 | Валидация решений: прогонять варианты экрана или флоу через персоны как через призмы |
| 6:30 | Связки дальше: из JTBD и паттернов → user stories, из раздражителей → требования к MVP, из триггеров → требования к онбордингу |
| 6:57 | Ограничение: персоны качественнее обычных, но это всё ещё не реальные люди — эффекта глубинок не дадут |
| 7:46 | Домашка: запустить директиву и вытащить из инсайтов 2–3 интересные фичи |
