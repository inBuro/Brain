# 4.9. Финальная директива — собираем среду — 12:05

Директива `release_environment` сворачивает накопленные директивы и историю работы в собственную AI-среду.

| Тайм-код | О чём |
| --- | --- |
| 0:00 | Директивы перестают быть файлами, которые дёргаешь руками, и становятся частью среды. Отличие одного дизайнера от другого дальше не в наборе директив, а в том, как он работает с агентом |
| 0:50 | **Три механизма зрелой среды**: навыки (агент включает сам), субагенты (исполнители под узкие задачи), оркестрация (правила раздачи) |
| 1:21 | **Главный принцип — простота.** Anthropic прямо рекомендует не усложнять: механика добавляется, только когда улучшает результат |
| 1:40 | Почему не брать готовые чужие среды: они собраны под других людей и принесут лишнее, которое будет впустую съедать контекст |
| 2:00 | **Почему директива читает живые доки**: архитектура сред у Anthropic пересматривается, зашитый снимок устареет. При каждом запуске берётся актуальная документация |
| 2:42 | Второй источник — **локальная история работы с агентом**: все разговоры лежат на компьютере (потому и видны при входе под другим аккаунтом). Директива их находит и вытягивает оттуда реальный опыт, ошибки и правки |
| 3:40 | Дальше собираются навыки, оркестрация и структура; старое **архивируется, не удаляется**, в конце выдаётся сводка |
| 4:03 | Вывод: среда строится не из головы, а из того, как ты реально работал — чем глубже погружался, тем богаче получится |
| 4:20 | **Навык (skill)**: раньше запускал директиву руками, теперь ставишь задачу, агент сам поднимает нужный навык. Грузится только когда нужен, поэтому их может быть много без раздувания контекста |
| 4:50 | **Оркестрация**: правила, что делать самому, какой навык поднять и что отдать субагенту |
| 5:00 | **Субагент**: отдельный исполнитель под узкую задачу, работает в своём окне и возвращает только результат. Независимые куски раздаются нескольким параллельно |
| 5:28 | Управление этим — через разговор: «вынеси это в навык», «сделай через субагента», «добавь правило в оркестрацию». Заучивать команды не нужно, нужно понимать принципы |
| 6:00 | **Лайфхак 1**: `CLAUDE.md` держать короче 200 строк — дальше работает плохо. Агент дописывает туда без предупреждения, за этим нужно следить |
| 6:48 | **Лайфхак 2**: навык срабатывает по описанию. Не включается — почти всегда размытое описание. Лечится уточнением, что он делает и когда применяется, плюс ключевые слова |
| 7:20 | **Лайфхак 3**: субагенты — это про параллель на независимых кусках. Линейную задачу они не ускорят, только добавят расход токенов и ожидание |
| 8:14 | **Две оговорки**: интерактив (например, правки в Figma через MCP) делает основной агент — субагента Figma не пустит. И субагент не видит вашу переписку: всё, что держится на решениях из разговора, проговаривать прямо в задаче |
| 8:40 | Субагент — более простая версия основного: одна маленькая машинная задача, не длинные рассуждения |
| 8:50 | Результат прогона: 27 навыков, 2 субагента (researcher и screen auditor), оркестрация в `CLAUDE.md` на 56 строк, 27 старых директив в архиве |
| 9:39 | Замечание автора по структуре: он бы попросил ещё один слой под артефакты, чтобы папки не расползались. Архитектуру среды каждый строит под себя, держась методологии Anthropic |
| 10:00 | **Как растить среду**: появилась повторяющаяся задача — заводишь навык; нужен отдельный исполнитель — субагента и правило вызова. Среда подстраивается под продукт, а не наоборот |
| 11:00 | Те же кирпичики работают за пределами дизайна: агент может вести кусок проекта — черновики статей, SEO, новые темы |
| 11:20 | Граница курса: довести помощника до автономной работы по расписанию — это уже инженерия (вызовы по API, SDK). Здесь взято ровно столько, сколько нужно продуктовому дизайнеру |
| 11:40 | Домашка: прогнать директиву и прислать скрин среды со скиллами и сводкой агента |
