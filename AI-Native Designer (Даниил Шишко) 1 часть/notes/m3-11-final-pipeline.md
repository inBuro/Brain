# 3.11. Финальный пайплайн + курсовой проект — 5:02

| Тайм-код | О чём |
| --- | --- |
| 0:00 | Задача курсового: не одна красивая картинка, а набор в едином стилевом языке, реально пригодный в продукте |
| 0:30 | **Сводный пайплайн модуля**: задача → выбор модели (по критериям, не по названию) → промпт и JSON → генерация → сборка → апскейл → результат |
| 1:35 | Блок сборки на усмотрение: ноды или руками по инструментам. Главное — прозрачный воспроизводимый пайплайн |
| 1:50 | Честная оговорка про ноды: тема на отдельный модуль, за раз не запомнится — нужно самому смотреть готовые примеры и экспериментировать |
| 2:20 | **Чек-лист продакшен-готовности**: разрешение под задачу, единый стиль, адаптация под 1:1, 16:9 и 9:16, чистота — никаких артефактов, шестируких людей и смазанного текста |
| 2:50 | Критерий простой: не отдал бы это в прод на реальном продукте — значит, результат сырой |
| 3:07 | **Что собирать по типам продукта.** Утилитарный (B2B, дашборд): логотип, 3–4 иллюстрации пустых состояний, промо-баннер. Пустых состояний вечно не хватает, и визуал там реально работает |
| 3:30 | Маркетплейс и e-com: карточка товара, лайфстайл-кадр, обложки категорий, продуктовый шот в сцене |
| 3:40 | Контент-продукт: обложки, иллюстрации, продуктовые шоты |
| 3:50 | **Минимум для всех**: единый стилевой язык плюс 5–7 артефактов. Лучше немного согласованного с прозрачным пайплайном, чем много невоспроизводимого |
| 4:10 | Сдача: ссылка на нодовый проект — и всё. Иначе нужно структурное описание, где что генерируется, в какой модели и почему |
| 4:39 | Альтернатива: собрать карту решений в FigJam вместе со средой и приложить туда реальные артефакты — но так сдавать сложнее |
