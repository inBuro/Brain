# 1.2. Рекурсивный брифинг — 8:51

Метод превращения трёх строчек от заказчика в структурированный бриф. Проблема, которую решает:
требования собираются случайно, по кусочкам, за 3–5 встреч на две недели, и всё равно чего-то не хватает.

| Тайм-код | О чём |
| --- | --- |
| 0:31 | Диагноз: нет системности, нет структуры вопросов, нет критерия «информации достаточно» |
| 1:03 | Фаза 1, расширение: 4–5 вопросов по категориям — пользователи, функциональность, тех. ограничения, UI/UX, бизнес. Цель — обозначить территорию задачи |
| 1:39 | Фаза 2, углубление: агент ищет дыры и противоречия, 2–3 раунда, после каждого summary «понятно / осталось выяснить». Отсюда и «рекурсивный» |
| 2:10 | Фаза 3, консолидация: бриф из всех раундов + отдельный список открытых вопросов к людям. Один звонок на 10 минут вместо пяти встреч |
| 2:40 | Разбор самой директивы: задача → роль → фазы → формат вывода → правила |
| 4:17 | Правила: вопросы порциями по 4–5, каждый с примером или вариантами, «не знаю» не продавливается, в бриф идут только подтверждённые данные |
| 4:47 | Демо на кейсе «дашборд для сервиса аренды VPS»; Claude Code рисует модальные окна с вариантами ответа |
| 5:19 | Готовый бриф в `.md`, читать через Open Preview: контекст, пользователи, сценарии, ограничения, UI-требования, метрики, открытые вопросы |
| 6:23 | Последний пункт брифа — scope; при выборе «полный продукт» агент пишет «делаем всё», при MVP — режет на этапы |
| 6:54 | Адаптация под тип проекта: меняются роль (e-com / мобилка / лендинг), категории вопросов и формат выхода |
| 8:02 | Домашка: выбрать продукт из списка в материалах, провести бриф, поправить директиву под свой тип продукта |

Директива: `directive_recursive_briefing.md`, роль по умолчанию — Senior UX Lead, enterprise B2B.
