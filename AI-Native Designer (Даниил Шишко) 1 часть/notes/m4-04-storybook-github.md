# 4.4. Storybook и передача на GitHub — 18:33

Две директивы: `storybook` собирает каталог компонентов, `handoff` заливает проект на GitHub.

| Тайм-код | О чём |
| --- | --- |
| 0:00 | Зачем каталог, если есть тестовая страница: сверить зеркало по каждому компоненту во всех состояниях и отдать работу в той форме, в какой её принято принимать |
| 0:40 | **Что даёт Storybook.** Компонент в изоляции — одна кнопка без шума вокруг |
| 1:00 | Все варианты и состояния сразу: primary, secondary, ghost — разработчик открывает и видит, как должно работать |
| 1:37 | **Песочницы** по группам компонентов — стенд, где видно взаимодействие компонентов и edge-кейсы |
| 2:00 | Форма передачи: живой каталог, из которого берут готовое и переиспользуют |
| 2:30 | Что добавлено в директиву сверх «собери Storybook»: песочницы (сам он их делает не всегда), структура, базовые анимации, привязка к переменным и неймингу |
| 3:11 | Разбор каталога: компоненты отдельными слотами, Foundation в своей подгруппе, у каждого состояния — копируемый код |
| 4:42 | **Табличный пример, почему это ценно**: у таблицы много нюансов — число колонок, переполнение текста, нехватка места. В каталоге все вариации видны сразу, а не всплывают по ходу разработки |
| 5:00 | По ходу просмотра сразу видно, что чинить: шапку таблицы нужно зафиксировать сверху — это говорится агенту тут же |
| 6:15 | **Песочницы на практике**: модалка (резко исчезает — просим анимацию), форма с состоянием ошибки, дропдаун с неправильным паттерном открытия |
| 7:00 | Дальше: навбар и его адаптивность, хлебные крошки, табы, пагинация с поведением на последних страницах |
| 7:49 | Отрабатывать такое на отдельных компонентах долго — стенд показывает поведение сразу |
| 8:00 | Дашборд серверов, создание сервера, пополнение баланса: тултипы, уведомление при копировании, пустые и ошибочные состояния |
| 9:20 | **GitHub по-дизайнерски**: репозиторий — папка проекта в облаке с историей; ветки — отдельные копии, где можно менять что угодно, не трогая основную |
| 10:00 | Живой пример из школы: общий репозиторий, ветка на каждого, изменения объединяются и уходят в `main` — «пушнуть в main» |
| 11:00 | Как это выглядит для дизайнера: свою фичу делаешь в отдельной ветке и пушишь в основную, когда работает |
| 11:40 | Обратный сценарий: разработчики дают тебе отдельную ветку от своего продукта, чтобы ты ничего не сломал в основной |
| 12:25 | Практика: зарегистрироваться на GitHub. Хороший тон — README, GitHub выводит его рядом с проектом |
| 13:30 | Подключение: claude.ai → Customize → Connectors → GitHub → Connect. После нового подключения чат или VS Code нужно перезапустить |
| 14:20 | Директива `handoff`: создаёт репозиторий или, если он есть, вносит изменения в отдельную ветку |
| 14:40 | Шаг 1 — создать репозиторий (можно сразу private) |
| 15:25 | Шаг 2 — токен: иконка профиля → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token, без даты истечения, все права |
| 16:00 | **Токен показывается один раз** — скопировать сразу и отдать агенту вместе с именем репозитория |
| 16:30 | Агент спрашивает, залить весь проект или только его часть; после пуша появляется ветка `main` и сгенерированный README |
| 16:55 | Готово — ссылку можно отдавать разработчику |
| 17:30 | Домашка: собрать Storybook, проверить песочницы и описания, при желании доработать анимации или расширить базу **прямо в Storybook, без Figma**, затем запушить на GitHub и приложить скрин репозитория |
