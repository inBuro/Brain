## Скиллы

Скиллы живут как 7 групп-мультискиллов (роутер → подскиллы → правила/принципы), и над всеми ними — `.claude/skills/skills-architect/SKILL.md`, инструмент, которым эта архитектура собрана и пересобирается; сам не вложен ни в одну группу. Поиск под задачу: [SKILLS_MAP.md](SKILLS_MAP.md) → роутер нужной группы; SKILL.md пачками не читать.

**Новый скилл — через онбординг** (`.claude/skills/meta/subskills/skill-onboarding/SKILL.md`): прочитать целиком, определить тип (знание/инструмент), построить карту пересечений, вшить в группу так, чтобы дополнял, а не дублировал. Инструменты (вендорские паки) не перелопачивать — только обвязка. **Пересобрать архитектуру целиком** (новые группы, слияние дублей, наведение порядка) — не онбординг, это `skills-architect` напрямую.

**Два ведра:** чтение по независимым веткам (поиск, ресёрч, аудит) — субагентам; всё, что пишет файлы, интерактивно или держится на контексте сессии, — основной контекст. Сомнение = основной контекст.

## Агенты

Персоны (accountant, analyst, copywriter, hiring-manager, m4l-master, project-manager, ux-researcher, ux-ui-designer, ableton-producer) вызываются двумя режимами с общей памятью — см. `agents/CLAUDE.md` (роутер + реестр `agents/meta/registry.md`). Канон персоны — `agents/<имя>/CLAUDE.md`; `~/.claude/agents/<имя>.md` — тонкий форвардер на канон для вызова через Task tool.
