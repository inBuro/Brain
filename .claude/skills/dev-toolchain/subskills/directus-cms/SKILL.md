# Directus CMS — контент отдельно от кода

Directus — open-source CMS: админка поверх обычной SQL-базы. Хостится на сервере пользователя, данные его. Контент живёт в коллекциях (аналог таблиц), продукт забирает его по REST API, редактировать может человек без кода. У Directus есть официальный MCP-сервер — ты работаешь со схемой и контентом напрямую, без ручной HTTP-обвязки.

## Порядок работы

1. **Выясни, есть ли уже Directus.** Спроси у пользователя адрес его Directus (или найди в проекте: `.mcp.json`, `.env`, docs). Нет инстанса → разверни на его VPS по [deploy.md](deploy.md), потом вернись сюда.
2. **Подключи официальный Directus MCP** (если ещё не подключён) — см. раздел ниже. Дальше всю работу со схемой и контентом веди через инструменты MCP, не через сырые curl-запросы.
3. **Спроектируй схему под задачу.** Из запроса пользователя выведи коллекции и поля. Каждое смысловое значение — отдельное поле с правильным типом и интерфейсом по [schema.md](schema.md). Запрещено складывать структурный контент в одно JSON-поле «чтобы быстрее»: пользователь потом не сможет нормально редактировать.
4. **Создай схему через MCP** (create-field / коллекции с типами и связями). Перед созданием прочитай текущую схему (read-collections, read-fields): если коллекции уже есть — дополняй, не пересоздавай и не дублируй.
5. **Наполни стартовым контентом** (create-item): перенеси реальный контент из кода продукта, если он там был; иначе 2-3 осмысленные записи, чтобы пользователь видел формат.
6. **Подключи продукт к API.** Публичное чтение: роли Public дай право read только на нужные коллекции — тогда фронт читает `GET {DIRECTUS_URL}/items/<collection>` без токена. В коде продукта замени зашитый контент на загрузку из API (fetch на этапе сборки или на клиенте — по стеку продукта). Картинки: `{DIRECTUS_URL}/assets/<file-id>`.
7. **Покажи результат:** ссылка на админку + что где редактировать, и подтверждение, что продукт тянет контент (поменяй запись — покажи, что на продукте обновилось).

## Подключение официального Directus MCP

Требуется Directus 11.12+. Токен: в админке Directus → Settings → Users → администратор → Token (static) → скопировать.

В Claude Code (из папки проекта):

```bash
claude mcp add directus \
  -e DIRECTUS_URL=https://cms.example.com \
  -e DIRECTUS_TOKEN=<static-token> \
  -- npx @directus/content-mcp@latest
```

После добавления перезапусти Claude Code. Проверка: вызови read-collections — должен вернуться список коллекций.

MCP даёт ~25 инструментов: коллекции и поля (read-collections, read-fields, create-field, update-field), контент (read-items, create-item, update-item, delete-item), файлы (read-files, import-file, update-files), flows. Права инструментов = права пользователя токена.

## Правила

- **Схема — только по [schema.md](schema.md).** Правильный тип и интерфейс под каждый формат: форматированный текст → WYSIWYG, картинка → файловое поле, дата → календарь, выбор → dropdown с choices, связи → настоящие реляции (M2O/O2M/M2M). Никаких голых JSON-полей под структурный контент.
- **У контентных коллекций** заводи служебные поля: `status` (published/draft/archived, дефолт draft), `sort`, `date_created`/`date_updated` (системные). Продукт показывает только `status = published`.
- **Безопасность:** админский токен живёт только в конфиге MCP и на сервере. Во фронтенд его не вшивать никогда. Для чтения с фронта — публичная роль с read на конкретные коллекции (или отдельный токен-читатель, если контент закрытый).
- **Повторный запуск дополняет, не ломает.** Новая просьба («добавь ещё FAQ») = прочитать схему → добавить недостающее → подключить. Существующие коллекции, записи и права не трогать без явной просьбы.
- **Не изобретай обвязку.** Всё, что умеет MCP, делай через MCP. Прямой REST — только для чтения с фронта продукта.
