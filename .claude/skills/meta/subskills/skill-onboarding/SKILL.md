# Онбординг нового скилла

**0 · Провенанс.** Источник, автор, дата, версия — строкой в шапке после установки (для вендорских паков — из `.claude-plugin/plugin.json`/`marketplace.json`, если есть).

**1 · Читка целиком ДО установки.** Что реально делает (description часто врёт), зависимости (скрипты, сеть, платные API), нет ли секретов, чужих путей, мёртвых хостов. Непрочитанное не ставится.

**2 · Развилка типа.** ЗНАНИЕ → глубокая интеграция (шаги 3–5 полностью). ИНСТРУМЕНТ/приложение (движок, скрипты, вендорный пак вроде gstack/better-skills/резюме-бандла) → внутренности не перелопачивать, только обвязка: маршрут в роутере группы, запись в SKILLS_MAP.md, починка путей/фронтматтера ровно настолько, чтобы исполнялся. ГИБРИД → софт не трогать, знаниевый слой размечать. Целое приложение со своими зависимостями и рабочей директорией → не скилл, отдельный проект вне `.claude/skills/`.

**3 · Карта пересечений.** По `SKILLS_MAP.md` (корень `~/Brain`) найти подходящую группу (`design`, `fadercraft`, `portfolio`, `dev-toolchain`, `meta`) и прочитать её роутер + соседние подскиллы. Вердикты:
- дубль → не ставится, уникальное (если есть) вливается в канон существующего подскилла;
- частичное пересечение → роли разводятся строкой в дедуп-вахте роутера, конфликты — явной пометкой, кто канон;
- дополнение → добавляется как есть.

**4 · Место.** Только внутри существующих пяти групп: `<группа>/subskills/<имя>/` (если скилл физически переносим) или строкой в индекс-таблице роутера (если это глобальный вендорский пак, который не переносится — по образцу того, как `portfolio` индексирует резюме-бандл, а `dev-toolchain` индексирует gstack). Новая группа на верхнем уровне — только явное решение владельца, не решение агента по ходу онбординга.

**5 · Вшивание.**
- Путь: физически переносимые скиллы → `<группа>/subskills/<имя>/`, честный фронтматтер (`name` = имя папки, `description` не переписывать бездумно — только если реально врёт).
- Роутер: строка в таблице «задача → подскилл» его группы.
- Дизайн/фронтенд-скиллы по умолчанию идут в глобальную группу `design` (`~/.claude/skills/design/`), а не в проектную копию — Fadercraft и другие продукты её потребляют, не дублируют.
- Принципы: если скилл несёт правило без объяснённого «почему» — не вшивать в `references/principles.md` группы, пока «почему» не найдено или не сформулировано с владельцем; правило остаётся как есть в самом скилле, просто не попадает в слой принципов.

**6 · Проверка и вахта.** Скрипты запускаются, MCP-зависимости резолвятся, пути внутри скилла (относительные ссылки на siblings) не сломаны переносом. Обновить счётчики в `SKILLS_MAP.md`. Оставшиеся пересечения — строкой на дедуп-вахту роутера группы. Вытесненное — на пенсию в `directives/_archive/` или `<группа>/_archive/skills-retired-<дата>/`, не удалять (если владелец явно не попросил удалить — тогда можно, как с симлинком `market-news-analyst`).
