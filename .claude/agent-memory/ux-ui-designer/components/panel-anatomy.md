Секция «panel anatomy» для Control XL. Показывает панель on-screen controls (мокка device-skin) слева и её controls объяснены текстом справа (desktop) / построчно с глифом (mobile).

**История ревизий (не откатывать по кругу, читай по порядку):**
1. v1: панель слева / текст справа, короткий tick перед каждой подписью, без построчной привязки.
2. v2 «mirror» (отменено): панель справа под идею fly-in анимации. **Анимация отброшена целиком.**
3. v3 «row-lock + широкие коннекторы-линии» (отменено): пользователь отклонил декоративные линии-мосты через зазор.
4. v4: панель слева, row-lock через ЧИСТОЕ выравнивание, БЕЗ какой-либо графики перед текстом.
5. **v5 — ФИНАЛ (2026-07-04, актуально)**: пользователь сам довёл десктоп руками в Figma и зафиксировал: (a) шапка (eyebrow/headline/lead) убрана целиком — секция теперь ТОЛЬКО панель+подписи+closing caption; (b) короткое тире «— » вернулось перед каждой подписью — но теперь это допустимо, см. правило ниже; (c) closing caption укорочена до «Key-mappable targets. Bind them to your keyboard»; (d) mixer-строка получила уточнение «(not available for key- or midi-mapping)».

**Правило про тире/коннекторы (уточнено 2026-07-04, ЧИТАЙ ВНИМАТЕЛЬНО — есть нюанс):**
- ✅ ОК: короткая горизонтальная чёрточка (rectangle ~19×1, bound к Semantic/Text/OnDark/Tertiary), сидящая ВПЛОТНУЮ к своей подписи как типографский лид-ин («— Switches…») — это часть визуального языка строки, не «мост через зазор».
- ❌ НЕ ОК: длинная линия/коннектор, которая тянется ЧЕРЕЗ зазор между панелью и текстом, визуально соединяя чекбокс и подпись как провод. Это отклонялось дважды (v3).
- Разница по сути: **inline-декор одной строки — да; floating leader-line между двумя разными объектами через пустое пространство — нет.**

### Row-lock математика (не изменилась в принципе, но ширина колонки теперь 666, не 886)

**Проверено 2026-07-04 после сужения колонки до 666**: все 4 подписи всё ещё однострочные (26px высота) — row-lock не сломан. Если колонка станет ещё уже — перепроверить перенос строк, иначе шаг 30 собьётся.

## Mobile v5 — decomposed rows (ГЛАВНОЕ изменение этой сессии)
Проблема была: на мобилке панель наверху (с чекбоксами) и текстовый список ниже читались как два несвязанных блока. Решение — **не через связующую графику, а через декомпозицию**: панель разбирается на составные части, и каждый чекбокс живёт в ОДНОЙ строке со своей подписью.

```
Layout=mobile (VERTICAL, gap density-4/16, padding sides density-6/24, width FILL)
├─ panel-header — клон titlebar панели (dot + "Control XL", мокка-скин, topLeft/topRight radius density-2/8) — единственное, что осталось от "окна" панели
├─ callouts (VERTICAL, gap density-4/16, width FILL)
│   ├─ AnatomyCallout ×4, Show Glyph=TRUE → [glyph 22×22, клон чекбокса с панели, мокка raw hex как есть] + [тире, Tertiary] + [текст, Body/Medium/Secondary]
│   ├─ mixer-spacer
│   └─ mixer line (dash + Caption, синхронизирован с desktop копией, БЕЗ glyph — Mixer это блок из 4 плиток, не один чекбокс)
└─ closing-caption (синхронизирован с desktop копией: "Key-mappable targets. Bind them to your keyboard")
```
Полная панель-инстанс (`Control XL`, весь body с чекбоксами) на мобилке БОЛЬШЕ НЕ используется — удалена из мастера, заменена на клон одной titlebar. Порядок строк = тот же порядок, что был в панели (Page→Bank→Daw→Prelisten), это и есть связь + теперь ещё усилена собственным glyph на каждой строке.

**Vertical alignment внутри AnatomyCallout**: `counterAxisAlignItems=CENTER` на атоме (не MIN!) — MIN ломал однострочные ряды (glyph/dash улетали к верху вместо центра строки). Для 2-3-строчных wrapped-рядов (напр. "Encoder Bank...") CENTER центрирует glyph/dash по всему параграфу — выглядит нормально, не идеально по первой строке, но приемлемо. `layoutAlign="MIN"` на отдельном ребёнке НЕ работает в текущем Plugin API (значение молча откатывается на "INHERIT") — если понадобится независимое top-align только для glyph, этот путь не сработает, искать другой механизм (напр. обёртка-фрейм с фиксированным padding).

**Component property**: `AnatomyCallout` теперь имеет BOOLEAN проп `Show Glyph#2604:1` (default false). Desktop-инстансы используют default (false, без glyph). Mobile-инстансы — `Show Glyph=true`. Правь через `instance.setProperties({"Show Glyph#2604:1": true/false})`.

## Известные ловушки (актуально, проверять первым делом при следующей сессии)
1. **Stray per-instance overrides** переживают правку master. Симптом: инстанс не совпадает с master (другая высота/видимость/текст). Фикс: `instance.resetOverrides()`.
2. **Stale render-cache по node-id** — иногда `get_screenshot` рендерит визуально сломанный/наложенный кадр даже когда все свойства через Plugin API верны. Фикс: `old.remove()` + `master.createInstance()` на том же месте (новый id, рендер сразу корректный).
3. **Пользователь правит мастер вручную в Figma между сессиями** — в этой сессии обнаружено: шапка исчезла, паддинги/gap появились raw (104/80/40 px, не токены), дэш вернулся как raw-цвет rectangle (Figma default grey `#D9D9D9`, не намеренный цвет), copy на инстансе разошлась с master (mixer-line/caption). **Всегда сверяй текущее состояние master+живого инстанса заново в начале сессии** — не полагайся на память о прошлой структуре, она могла измениться руками пользователя.
4. **Live-инстансы могут переехать на другую страницу файла между сессиями** (в этот раз — с фрейма «123» на страницу «Cotrol XL» / `ProductPage · *`). Проверять актуальную локацию, а не доверять старым node id из памяти.

## DS-долги, закрытые в этой сессии
- Дэш-rectangle в атоме `AnatomyCallout` — был raw hex (`#D9D9D9`, Figma default) → привязан к `Semantic/Text/OnDark/Tertiary` (тот же токен, что уже был на mixer-line дэше).
- `desktop.paddingTop` 80 → bound density `20`. `content.itemSpacing` 40 → bound density `10`. `desktop.paddingLeft/Right` 104 (raw, не токен) → снято до 96 = density `24` (визуальная разница ±8px, малозаметно).
- Master mixer-line/closing-caption text синхронизирован между desktop и mobile (раньше расходились — mobile всё ещё показывал старую длинную копию).

## Открытые семантические флаги (НЕ чинил сам — на решение пользователя/копирайтера)
1. **Противоречие смысла**: closing caption теперь звучит как общее «Key-mappable targets. Bind them to your keyboard» (подразумевает все контролы мапятся на клавиатуру), а mixer-строка explicitly говорит «(not available for key- or midi-mapping)» — то есть Mixer recall НЕ мапится. Это прямое смысловое противоречие между соседними строками одной секции — нужно решение пользователя (либо смягчить caption, либо явно исключить Mixer из его формулировки).
2. Closing caption также потеряла упоминание **MIDI** (было «Key- and MIDI-mappable», стало только «Key-mappable») — при этом mixer-строка ссылается на «key- or midi-mapping» как на существующую пару возможностей. Если MIDI-маппинг всё ещё актуален как фича — стоит вернуть его в caption, иначе mixer-строка ссылается на что-то, что caption больше не упоминает.

## Trade-offs
- Mixer-строка не идеально центрирована по блоку плиток 11-14 на панели (approx, ±10px) — решено как приемлемое (association by proximity), не пиксель-перфект как у 4 основных callouts.
- Row-lock (desktop) работает только пока все 4 подписи однострочные при текущей ширине колонки (666px) — если копирайт станет длиннее, шаг 30px собьётся, нужно перепроверять.
