## 2026-07-13 (дополнение) — Bug 1 РЕАЛЬНАЯ причина: live.colors токен без live_-префикса

**Симптом:** иголка/дуга `obj-31` (`dial`) чёрная в Standard-режиме. В Follow Track — цвет трека (через JS outlet 5) виден нормально.

**Корень:** цепочка нативной темы `dev_ndq` → `dev_ndc` (`live.colors`) → `dev_ndr` → `dev_ndpak` → `obj-31` запрашивала `live.colors` токеном `"dial_needle"` (без `live_`-префикса). `live.colors` не резолвит короткую форму для этого токена → возвращает `dial_needle 0 0 0 1` (чёрный RGBA по умолчанию). `route dial_needle` совпадает → `prepend needlecolor` → obj-31 = чёрный. Этот overwrite происходит при каждом `emitMode()` (init + переключение режима) → перекрывает правильный циан из SA-биндинга.

**Почему Follow работал:** в Follow-режиме JS напрямую шлёт `outlet(5, r, g, b, 1.0)` → яркий трек-цвет → перебивает чёрный. `emitMode()` в Follow НЕ запускает эту цепочку (`sel 1` не матчит 0).

**Фикс:** `dev_ndq` text `"dial_needle"` → `"live_dial_needle"` + `dev_ndr` text `"route dial_needle"` → `"route live_dial_needle"`. Теперь цепочка корректно запрашивает тему → получает cyan → obj-31 needle = theme-cyan в Standard. md5 `4e5b01d2` (74772 B).

**Правило (ЗАПОМНИТЬ):** `live.colors` в Max принимает ПОЛНОЕ имя с `live_`-префиксом (`"live_dial_needle"`, `"live_lcd_control_fg"` и т.д.); `route` тоже должен матчить это полное имя. Короткие токены без `live_` могут работать для НЕКОТОРЫХ имён (например `lcd_control_fg` как alias), но не для всех — в частности `dial_needle` без префикса возвращает чёрный. SA-выражения (`themecolor.live_*`) ТРЕБУЮТ `live_`-префикс. Итого: для `live.colors` используй `"live_dial_needle"` (с `live_`); для SA `themecolor.live_dial_needle` (с `themecolor.live_`).
