**Финальный рабочий рецепт цветов DF Slot (2026-07-10, v21–v23, впервые ПРАВИЛЬНО).** Это выжимка «как», а не история — детальный wiring/md5/версии в [[df-slot-multimap-panel]]. Правится **только** `MapButtonTint.maxpat` (DF-копия общего MapButton, влияет на ВСЕ 9 инстансов: главный `df_mapparam` + 8 слотов панели) + `midi_learn_slot.js` (ink/эмиссия трека) + device-level в `DF Slot.amxd` (mm_icon). Общие `MapButton.maxpat`/`multimap.maxpat` НЕ трогать.

## ⚠️ Max re-save ЗАПЕКАЕТ рантайм-цвет и СТИРАЕТ SA (реально било 2026-07-10)
Когда пользователь пересохраняет девайс в **Max-редакторе** (Cmd-S), Max материализует ТЕКУЩИЙ рантайм-цвет элемента (то, что нарисовано в момент save — обычно цвет активного трека, лайм-зелёный `[0.9686,0.9569,0.4863]`) в **статические** цвет-атрибуты И **обнуляет SA-expression** (`themecolor.*` → `""`, либо вообще удаляет SA-запись). Элемент намертво окрашивается, тема больше не рулит. Бьёт по рантайм-driven атрибутам (`mm_icon` глиф bc/tc/toc/atc/atoc; `obj-31` needlecolor). Корень — не наша правка, а **user сохраняет девайс в Max**. Лечение: восстановить статик = materialized-fallback нужного токена + вернуть SA-expression (сверять с последним «здоровым» бэкапом до пересохранения). Проверенные значения: `live_lcd_control_fg` = амбер `[1.0,0.6784313725490196,0.33725490196078434,1.0]`; `live_dial_needle` = сине-барвинковый `[0.5450980392156862,0.7725490196078432,1.0,1.0]`. Диагностика: грепать по `0.48627450980392156` (лайм-B) на `expression: ""`/без-SA. Wiring при этом ЦЕЛ — трогать только статик+SA.

## Ловушки, которые надо знать ПЕРЕД правкой цвета (все реально били)
1. **Какой атрибут реально рисует текст.** `obj-14` (Map) и numbox Min/Max — это **live.text appearance 2** и **live.numbox appearance 4 = LCD**. Видимый текст/цифру рисует **`lcdcolor`**, а НЕ `textcolor`/`textoffcolor` (для appearance-2/4 они не отрисовываются). ON-заливка кнопки = `bgoncolor`/`activebgoncolor` (непрозрачные). Рамка = `bordercolor`. Тёмный фон LCD = `lcdbgcolor`. Красить надо ИМЕННО отрисовывающий атрибут, иначе фанаут «доходит», а глазом пусто.
2. **Нативный драйвер `obj-39` (`p setButtonColor`) клобберит.** На КАЖДОЙ смене состояния он заново пушит `lcdcolor`/`lcdbgcolor`/`inactivelcdcolor`/`focusbordercolor` из темы — перетирает любые внешние пуши. Чтобы надёжно перебить: перехватить связь `obj-39[0]→obj-14[0]` вставкой `[route lcdcolor]` — амбер-`lcdcolor` уходит в outlet0 = DROP, а тёмный `lcdbgcolor`/`inactivelcdcolor`/`focusbordercolor` проходят outlet1→obj-14 (нативный сток-фон цел). Без этого — гонка, амбер проскакивает.
3. **Токены-ловушки.** В теме юзера И `live_control_selection`, И `live_lcd_control_fg` резолвятся в **АМБЕР/салмон** — это НЕ нейтральный «сток». Нейтральный приглушённо-серый = **`live_lcd_control_fg_zombie`**. Для `live.colors` ключ КОРОТКИЙ (`lcd_control_fg_zombie`, `lcd_bg`) БЕЗ префикса `live_`; префикс `live_` только в SA-выражениях `themecolor.*`.
4. **`gate` НЕ переотправляет.** Max-объект `gate` при открытии НЕ ре-эмитит сохранённое значение — только пропускает НОВЫЙ вход. Поэтому на каждый кадр/вход-в-state банг источника (пака) делать ЯВНО (триггером), иначе цвет «залипает» на том, что нарисовал драйвер.
5. **«mapped» ≠ obj-14 value.** `obj-14` value = **ARMED-флаг** (1=arming/blink, 0=idle И mapped И unmapped). Реальный «mapped» = `obj-16[6]` (target id, `!=0`). Путать → mapped-idle красится нативом, arm не инвертируется.
6. **Контраст текста = перцептивная яркость (HSP), не сумма каналов.** `inkFor`: `hsp = sqrt(0.299·r² + 0.587·g² + 0.114·b²)`, `hsp > 0.5 → чёрный [0.06]`, иначе `белый [0.96]`. Наивная `sum(rgb)>1.5` мис-скорит насыщенный оранж трека (`[0.965,0.424,0.012]` sum=1.39<1.5 → давал белый на светлом фоне = размытый серый). HSP того же оранжа = 0.62 → чёрный. Живёт в `midi_learn_slot.js`, `inkFor()`.
7. **Наш «дефолтный» бёрнт-оранж-литерал = `[0.9647, 0.4235, 0.0118]` (RGB 246,108,3).** Это НАШ мусор, не палитра. **Грепать по `0.964`, НЕ `0.965`** (строка начинается `0.9647` — греп по `0.965` промахивается; из-за этого он «жил» несколько заходов). Заменять на токены.
8. **live.text inlet0 attr-msg не эмитит value** → цвет-сообщения (`lcdcolor …`/`lcdbgcolor …`) в obj-14[0] петель не создают, даже если по графу «кольцо».

## ⚠️ live.colors — как найти правильный токен (2026-07-13, реверс)
**Авторитетный источник токенов live.colors:**  
`/Applications/Ableton Live 12 Suite.app/Contents/App-Resources/Max/Max.app/Contents/Resources/C74/interfaces/maxcolors.json`

Каждая запись: `id` (snake_case `live_xxx` — используется в SA `themecolor.<id>`) + `label` (строка с пробелами/заглавными — **именно это имя шлют в `live.colors`**) + `oncolor` (RGBA в теме по умолчанию).

**Критические находки:**
- `live_dial_needle` (label `"Control Needle On"`) → `oncolor [0.157, 0.157, 0.157, 1.0]` = **ТЁМНО-СЕРЫЙ** (цвет иголки-указателя, не дуги)
- `live_value_arc` (label `"Control On Variant"`) → `oncolor [0.427, 0.843, 1.0, 1.0]` = **ЯРКО-ЦИАН** (цвет заполненной дуги `live.dial`/`dial`)
- `live_dial_fg` (label `"Control Range On"`) → `oncolor [0.157, 0.157, 0.157, 1.0]` = тёмно-серый (шкала диапазона)

**Формат запроса live.colors:** кавычки нужны только для multi-word символов. В max-патче message-бокс `"Control On Variant"` — кавычки внутри текста = разделитель Max-символа. В AMXD JSON: `"text": "\"Control On Variant\""`. `route "Control On Variant"` матчит ответ live.colors. **Короткие токены БЕЗ `live_`-префикса** (напр. `lcd_control_fg_zombie`, `dial_needle`) — **не работают** для multi-word: live.colors возвращает `0 0 0 1` (чёрный). Prefixless `dial_needle` не давал результата — вот почему v29-v30 давали тёмный цвет.

**SA vs live.colors — разные системы:**
- `themecolor.<live_xxx>` (saved_attribute_attributes expression) — применяется на загрузке, **до** `live.thisdevice` bang; любой поздний `message needlecolor R G B` перебивает SA
- `live.colors "label"` — рантайм-запрос (bang → ответ → route → prepend → attribute message), используется для обновления цвета при смене режима
- Они должны ссылаться на ОДИН и тот же токен (одна подтягивает при load, другая при смене режима)

**Max-редактор СТИРАЕТ SA при save (уже в recipe выше):** сохранение в Max запекает рантайм-цвет (обычно цвет трека или дефолт) и обнуляет `expression: ""`.

## Стейт-машина (ядро, MapButtonTint)
`it_state [expr ($i4*(($i1||$i2)))*((($i1*($i2==0))+($i2*$i3))+1)]`, где i1=M(mapped=`obj-16[6]!=0` через `it_mflag`), i2=V(armed=obj-14 value), i3=Ph(фаза независимого `[metro 120]`+`[counter 0 1]`), i4=isFollow(`it_isf`).
- **state 0 = native/cold** = {Standard любое, Follow-unmapped-idle}
- **state 1 = waiting** = arm && Ph=0
- **state 2 = bright** = mapped-idle ИЛИ (arm && Ph=1)
`it_stfan [t i i]`: правый (первым) → компараторы ставят гейты, левый (вторым) → `it_stsel [sel 0 1 2]` эмитит. Гейты: `it_dg` open=(state0), `it_bgg`/`it_txg` open=(state2), `it_wbgg`/`it_wtxg` open=(state1). В state 0 доп. развилка по isFollow через мули `it_zctl`/`it_ctctl` (см. таблицу).

## Arm-мигание (правильный способ — оба кадра САМИ, натив выключен)
Опираться на нативный драйвер для «ждущего» кадра НЕЛЬЗЯ: в теме юзера натив-«ожидание» = АМБЕР (не зелёный). В FOLLOW+arm держать `it_dg` закрытым в ОБЕИХ фазах (state 1 и 2, никогда 0) и рисовать оба кадра самим:
- **Ph=1 (bright):** `lcdbgcolor`=трек (`it_bgpak`), `lcdcolor`=инверс (`it_txpak`, ink ch7-9 из js).
- **Ph=0 (waiting):** `lcdbgcolor`=тёмный `lcd_bg` (`it_wbgpak` ← `live.colors lcd_bg`), `lcdcolor`=**трек** (`it_wtxpak`, ch1-3).
Итог FOLLOW: пульс [трек-текст на тёмном] ↔ [чёрный на трек-заливке]. Ноль амбера. mapped-idle = state 2 bright статик (та же bright-ветка, без метро).

### ⚠️ STANDARD+arm = НАТИВНЫЙ blink obj-39 (v29, 2026-07-10). Follow+arm = наш кастом. Читать перед любой правкой arm/state.
**Разделение режимов (финал):** STANDARD-arm мигает СТОКОВЫМ нативным blink драйвера `obj-39` (обходим свои перехваты); FOLLOW-arm мигает нашим кастомом (state1↔2 трек↔инверс). `sa_*` (кастомный Standard-blink генератор) — **УДАЛЁН как тупик** (не работал, давал залипания; `DFB_AND` в логе всегда 0). Все `dbg_dfb_*` принты — удалены.
**Как obj-39 делает нативный blink (изучено по пристине `MapButton.maxpat` `5e75459e`, субпатч `p setButtonColor`):** метро `qmetro 200` внутри obj-39 стартует НЕЗАВИСИМО от нашей логики — его гоняет мэппинг-подсистема (`obj-16[5]→obj-39[2]` = RangeAndName outlet5 → `sel 1` → start). Атрибут blink = **`lcdcolor` с пульсирующей АЛЬФОЙ** темы `lcd_control_fg`: toggle→`gate 2`→ Ph0=`lcdcolor …0.5`(dim)/Ph1=`lcdcolor …1.`(bright). lcdbgcolor/inactivelcdcolor не пульсируют (только на смене state). Т.е. нативный сток-пульс = амбер-текст мерцает alpha 0.5↔1.0 на тёмном lcdbg.
**Почему Standard не мигал (регресс v22):** (1) `it_rt [route lcdcolor]` вставлен `it_dg[0]→it_rt[0]`, `it_rt[1]→obj-14`: амбер-lcdcolor (в т.ч. blink-пульс) уходит в outlet0 = DROP. (2) наш `it_armmetro [metro 120]` крутит recompute каждые 120мс в Standard (state≡0) → `it_stsel[0]` → зомби-статик амбер перетирает.
**Решение (проще sa_*, 3 бокса, опора на натив):**
- **Пропуск нативного пульса:** `it_rt[0]` (дропнутый lcdcolor) → `nb_g [gate]`[1] data → `obj-14[0]`. Гейт control = `nb_ctl [* 0]` (hot←`obj-14[0]`=V armed, cold←`it_isstd[0]`=Standard) → open только при V·Standard.
