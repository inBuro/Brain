# Каталог воркфлоу

Одна строка на команду: в какой момент за ней тянуться и что остаётся после. Порядок внутри модулей — рабочий: каждая следующая ест выход предыдущей.

## Служебные

| Команда | Когда звать | Остаётся |
| --- | --- | --- |
| `/init-project` | новый проект начинается с пустой папки | папки, свой `CLAUDE.md`, строка в корневом реестре |

## Модуль 1 — понять, что строим

| Команда | Когда звать | Остаётся |
| --- | --- | --- |
| `/brief` | есть хотелки заказчика, нет задачи | `brief.md` — пользователи, функциональность, ограничения, открытые вопросы |
| `/research-quick` | надо быстро понять поле боя | обзор конкурентов за полчаса |
| `/deep-research` | быстрого обзора мало, нужен настоящий ресёрч | промпт под Gemini Deep Research |
| `/competitors` | оба ресёрча собраны, нужны выводы | SWOT, разбор фич, UX-паттерны, финальный документ |
| `/ux-audit` | продукт уже существует и его надо чинить | отчёт по проблемам с привязкой к скриншотам |
| `/personas` | решения принимаются «за всех сразу» | персоны с болями и сценариями |
| `/interview` | гипотезу надо проверить до макетов | протокол интервью от лица персоны |
| `/scope` | хотелок больше, чем времени | список фич, приоритеты, граница MVP |
| `/prd` | пора отдавать команде и фиксировать | PRD + страница в Notion |
| `/notion-mcp` | агент не умеет писать в Notion | подключённый MCP |

## Модуль 2 — превратить документ в экраны

| Команда | Когда звать | Остаётся |
| --- | --- | --- |
| `/figma-mcp` | агент не видит Figma | подключённый MCP + справочник инструментов |
| `/sitemap` | PRD есть, структуры нет | карта экранов и user flow на FigJam |
| `/wireframes` | структура есть, экранов нет | вайрфреймы 3–5 ключевых экранов |
| `/ds-baseline` | дизайн-системы нет вообще | токены, Variables, семь базовых компонентов, `ds/CONTRACT.md` |
| `/ds-scan` | дизайн-система есть, но агент её не знает | `ds/foundation.md` и `ds/components.md` |
| `/ui-kit` | базовых компонентов не хватает | кит расширен пакетами по 2–3 компонента |
| `/variants` | компонент есть, состояний нет | матрица variants × states × sizes + токены под состояния |
| `/final-screens` | вайрфрейм пора одеть в компоненты | экран, собранный из instance, а не нарисованный заново |
| `/screens-audit` | экранов много и они разъехались | отчёт по шести проверкам, автофикс только с апрувом |

## Модуль 3 — визуальный язык

| Команда | Когда звать | Остаётся |
| --- | --- | --- |
| `/brand-direction` | генерации выходят разностильными | `brand-direction.md` — манифест, который подставляется в промпты |
| `/video-storyboard` | нужен ролик, а не набор картинок | раскадровка + промпты image-to-video |

## Модуль 4 — довести до работающего прототипа

| Команда | Когда звать | Остаётся |
| --- | --- | --- |
| `/react-base` | макеты пора сделать кликабельными | Vite + React + TS с зеркалом дизайн-системы |
| `/storybook` | компонентов много, показать нечего | каталог со стори и автодоками |
| `/handoff` | пора отдавать разработке | репозиторий на GitHub и ссылка |
| `/screens` | нужен конкретный экран в коде | экран из фрейма Figma + запись в реестре |
| `/wire` | экраны есть, но мёртвые | навигация, мок-данные, формы, состояния, edge-cases |
| `/deploy` | прототип надо показать живым людям | публичная ссылка |
| `/dashboard` | тесты идут, данные нигде не собираются | трекер, сборщик событий, дашборд метрик |
| `/release-env` | директив накопилось больше, чем помнишь | среда: навыки, субагенты, оркестрация |
