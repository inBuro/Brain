# SEO-аудит 2026-08-16 — бриф для агента

**Summary**: Внешняя проверка индексации `fadercraft.com` (по индексу Google + почте, без доступа к проду и репо лендинга) вскрыла: сайт перестроен и содержит продукт, которого нет в [[roadmap]]; в индексе висит preview-деплой Cloudflare Pages; судьба `/free-custom-modes` под вопросом. ## 0. Как читать эту страницу

Всё ниже получено **без доступа к проду и к коду сайта**. Ограничения окружения на момент аудита:

- `fadercraft.com`, `maxforlive.com` и preview-хост `*.pages.dev` — заблокированы egress-политикой окружения.
- Репозиторий лендинга недоступен: `list_repos` отдаёт только `inBuro/Brain` и `inBuro/Chess-Demo`.
- Коннектор Google Search Console не подключён — отчёты (показы/клики/страны/запросы) не читаются.
- В подключённом почтовом ящике **нет ни одного письма Gumroad** — аккаунт продавца заведён на другую почту, данные о продажах недоступны.

Поэтому у каждого факта ниже проставлен статус: **✅ подтверждено** (виден в индексе Google), **❌ опровергнуто** (вики расходится с наблюдаемой реальностью), **❓ не проверяемо** (нужен доступ).

⚠️ Отдельная оговорка про метод: поисковая выдача **не является полным дампом индекса**. Отсутствие страницы в результатах — повод проверить, а не доказательство деиндексации.

## 1. Исходный вопрос основателя

> «Имеет ли смысл перевести страницы с гайдами на французский, uk English, немецкий, для лучшего индекса в этих странах?»

**Вердикт: нет, не сейчас. Вариант en-GB не имеет смысла и в перспективе.**

Аргументы:

1. **Аудитория ищет по-английски.** SEO-таргеты проекта (`docs/superpowers/specs/2026-05-01-fadercraft-launch-design.md:154`) — `launch control xl mk3 max for live`, `lcxl mk3 ableton mapping`. У этих терминов нет немецких/французских эквивалентов: «custom mode», «Max for Live», «sends», «encoder bank» немцы и французы гуглят как есть. Локализованная страница целится в запросы с околонулевой частотностью, а на английский запрос из Германии английская страница ранжируется и так.
2. **en-GB — это орфография, а не язык.** Бонуса в британской выдаче за неё нет; получается дубль контента, hreflang-развилка и canonical-риск при нулевом апсайде. Для UK работают ссылки и упоминания, не перевод.
3. **База не готова.** В индексе четыре страницы, одна из бывших ключевых под вопросом (см. §3), содержимое `sitemap.xml` неизвестно, плюс дубль всего сайта на preview-хосте. Локализация в такой конфигурации умножает проблему, а не решает её.
4. **Стоимость не разовая.** Копи живая (терминология менялась: `signals → sources`, `gumroad-description-sends-follower.md:113`). Каждая правка формулировки превращается в 4 правки на языках, которые никто не проверит. Протухший перевод хуже отсутствия перевода.
5. **LLM-поиск.** По нишевым техническим темам ассистенты цитируют преимущественно англоязычные источники.

**Условия для пересмотра** (проверяются по GSC, см. задачу D1):

- английский органик даёт стабильный поток (ориентир ≥1000 сессий/мес);
- в отчёте «Страны» по DE/FR видны **показы с нормальной позицией, но низким CTR** — только это доказывает языковой барьер, а не отсутствие видимости;
- есть страница-победитель, которую есть смысл клонировать (переводят выигравший контент, а не всё подряд).

Тогда переводить не сайт целиком, а одну-две страницы, руками, с hreflang. Список языков пересобрать по данным: по объёму Ableton-аудитории DE обычно интереснее FR, а ES/PT-BR/JP нередко крупнее обоих.

Отдельная история — **перевод Quickstart для покупателей**. Это не SEO, а качество продукта; окупается, когда появится заметная доля покупателей из конкретной страны.

## 5. Очередь задач для агента

Порядок блоков — это порядок исполнения. Блок A гейтит B и C.

### A. Доступы (гейт, исполнитель — человек)

- [ ] **A1. Выдать один из трёх доступов.** Без любого из них блоки B/C неисполнимы:
  1. установить GitHub App на репозиторий лендинга (`fadercraft-landing`) → проверка по коду;
  2. разрешить `fadercraft.com` и `maxforlive.com` в network policy окружения ([документация](https://code.claude.com/docs/en/claude-code-on-the-web)) → проверка живого прода;
  3. подключить коннектор Google Search Console → отчёты напрямую.
  **Готово, когда:** агент может прочитать `sitemap.xml` любым из способов.

### B. Сверка фактов (после A)

- [ ] **B1. Инвентаризация `sitemap.xml`.** Сверить список `<loc>` с фактическими роутами. Зафиксировать расхождения.
  **Готово, когда:** в этой странице появился список URL из sitemap и вердикт «актуален / устарел».
- [ ] **B2. Судьба `/free-custom-modes`** (высокий приоритет). Ответить: роут существует? отдаёт 200/301/404? есть ли в sitemap? что говорит GSC → Индексирование → Страницы?
  **Готово, когда:** статус страницы назван однозначно и, если она мертва, названа причина.
- [ ] **B3. Аудит индексируемости по всем роутам** — `robots.txt`, `<link rel=canonical>`, `meta robots`, заголовки. Проверить, что canonical указывает на апекс, а не на pages.dev.
- [ ] **B4. Проверить роуты `/sf`, `/update`, `/sends-follower/updates`** и синхронность `_redirects` с [[outbound-links]].
- [ ] **B5. Статус Control XL v1.1** — `api/version.json` `latest`, версия и «Last Updated» в листинге maxforlive 15522, упоминание v1.1 в описании Gumroad.

### C. Фиксы

- [ ] **C1. Закрыть preview-хосты от индексации** (главный подтверждённый дефект). Отдавать `X-Robots-Tag: noindex` либо `Disallow: /` для любого хоста кроме `fadercraft.com` (в Cloudflare Pages — через middleware/Function или `_headers`; `_redirects` для этого не годится), затем убрать уже проиндексированный URL через **GSC → Удаления**.
  **Готово, когда:** preview-URL отдаёт noindex, заявка на удаление подана, брендовый запрос перепроверен через неделю.
- [ ] **C2. Пересобрать и отправить `sitemap.xml`** со всеми актуальными роутами, запросить индексацию через «Проверка URL». Закрывает `roadmap.md:356`.
  **Готово, когда:** в GSC sitemap в статусе «Успешно», число обнаруженных URL совпадает с числом реальных страниц.
- [ ] **C3. Решение по `/free-custom-modes`** — по результату B2: восстановить страницу либо поставить 301 на релевантный роут. Молча терять бывшую точку входа нельзя.
- [ ] **C4. Проверить, что три продуктовые страницы связаны внутренними ссылками** с хаба и футера — страница без входящих ссылок остаётся сиротой даже после индексации.

### D. Данные под решение о локализации

- [ ] **D1. Выгрузить GSC → Эффективность за 3 месяца**, вкладки «Страны» и «Запросы», CSV положить в `_Inbox/`.
  **Готово, когда:** по DE/FR/GB известны показы, CTR и средняя позиция.
- [ ] **D2. Свести страны покупателей** из Gumroad (нужен доступ к ящику продавца или CSV-экспорт).
- [ ] **D3. Вынести вердикт по локализации** по критериям из §1 и записать в эту страницу. **До закрытия D1 переводы не начинать.**

### E. Гигиена вики

- [ ] **E1. Привести [[roadmap]] в соответствие с фактами** — снять устаревшие блокеры Sends Follower, добавить роуты `/control-xl` и `/dynamic-focus`, завести пункт про preview-индексацию, обновить шапку `Last updated`.

### Анти-лист (в этом заходе НЕ делать)

- ❌ Не плодить новые страницы ради SEO, пока не закрыты C1–C3: на домене из четырёх страниц дубли и сироты дороже недостающего контента.
