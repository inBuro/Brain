## 2026-08-10 — Removed the manual Connect button, cold-start onboarding redesign, version 0.4.7 shipped

Triggered by GA4/PostHog/CWS install-count confusion (see below), which led into a full redesign of the cold-start flow: no more manual "power on" step, decks connect themselves.

**Analytics detour that started the session:** GA4 extension property showed 1 install/month (real cause: `chrome.runtime.onInstalled` → GA4 Measurement Protocol call from the MV3 service worker is unreliable — worker can be torn down before the fetch lands, no retry). CWS Developer Dashboard (Analytics → Installs & uninstalls) is the actual source of truth for install counts (12 installs/1 uninstall for the period) — Google tracks that at the store level, independent of extension code. PostHog's low numbers (5 users) were separately explained: the extension had only been publicly listed 3 days (CWS approved 2026-08-07), no promo posts live yet, so 5/12 activating past install is a normal early-funnel number, not a tracking gap. Added a parallel `posthog.capture('extension_installed')` HTTP call from `chrome.runtime.onInstalled` in `background.js` as an independent (if similarly best-effort) install signal, separate from GA4.

**Onboarding/cold-start redesign:**
- Removed the manual ⏻ "Connect" click entirely. `attemptAutoConnect()` (new, in `sidepanel.js`) now connects any deck that has a picked tab but isn't live yet — called from `refreshTabs()`'s poll and right after a manual pick from a deck's ▾ menu. Cold start (both decks picked at once) and "completing an already-live pair" both go through this one path now.
- `#connect` lost its power-on state — it's purely the swap control now (`updateConnectEnabled()`, replacing the old `isConnected`/`setConnected`/`partialMode` machinery), enabled as soon as *either* deck has a track (not just when both are live) so a track can be swapped into an empty slot too. `swapDecks()` now also calls `updateDeckConnectedVisual()` on both decks post-swap, since swap can change a box's connected/empty status, not just trade two already-live decks.
- Empty-deck placeholder copy: "Open a YouTube tab with a track to start mixing" (`_locales/en/messages.json` `deckEmptyHintB`, shared by both decks' spans), tinted per deck to that deck's own play-button accent color (`--color-accent-deckA`/`B`) instead of neutral grey. Non-breaking space between "to" and "start" (widow prevention).
- Top status hint ("Open YouTube tabs to start mixing") removed — `refreshTabs()` no longer sets it on the empty-tabs branch.
- Feedback button icon: pencil (✎) → speech-bubble (💬); dropped a leftover `transform: scaleX(-1)` on `#feedbackBtn` left over from the old pencil glyph (was putting the bubble's tail on the wrong side).
- Tempo crossfader bar (`#tempoStatus`) is now always rendered instead of popping in/out based on both-decks-connected — `bpmLabel()`/`ratePercent()` already degrade gracefully with 0 or 1 deck live.
- `.deckThumb` gets `overflow: hidden` — suppresses the broken-image glyph WebKit/Blink draws when a stale thumbnail `src` 404s after its YouTube tab closes in the background.

**Playback-state bugs found while testing the above (all direct reports mid-session):**
- Fresh auto-connect could land a deck audibly playing instead of paused: `video.pause()` in `counterDJSetup` was a single call, and YouTube's own player could re-assert autoplay moments later (tab was still buffering/initializing), which the next `counterDJPoll` tick then read as legitimate. Fixed with an in-page guard: a `play` event listener on the video that re-pauses for a 4s settle window after connect, cancelled early by `counterDJTransport`'s `restart` action so a real Play click always wins even inside the window. Known gap: a click on YouTube's own play button in that same 4s window looks identical to autoplay resuming and gets paused right back; past ~4s it's honored normally.
- `disconnectDeck()` reset `state.decks[deck].playing` but never cleared the Play button's `.isPlaying` CSS class (that lived only in `updateReadouts()`, which disconnect doesn't call) — left a stale glow on a button that had gone back to disabled. Moved the `.isPlaying` toggle into `updateDeckConnectedVisual()` too.

## 2026-08-10 — Connect-time force-pause and swap level-meter bugs fixed (direct reports)

Resolves the "reconnect/connect force-pauses a running set" question left open in the 2026-08-10 entry above — answer turned out to be no, it must not.

- **`counterDJSetup` (`sidepanel.js`) no longer force-pauses a track that's already playing when it attaches.** Previously `video.pause()` ran unconditionally on first setup, so connecting GrooveMix mid-set always stopped whatever was already playing — and because the stop set `state.decks[key].playing = false`, the next Play click hit `counterDJTransport`'s `restart` action, which seeks `currentTime = 0`, throwing away the track's position entirely instead of resuming it.
  - First attempt gated the pause on raw `video.paused` at attach time — wrong signal: a freshly opened YouTube tab autoplays by default, the exact same outward state as a genuinely mid-set track, so on a cold-start pair the *second* (guest) deck also skipped the pause and landed already "playing" (direct report, screenshot of deck B's lit Play button). Superseded within the same session.
  - Correct signal, mirroring the EQ-cut logic already in `connectDecks()`: whether the *sibling* deck is already connected-and-playing (`otherAlreadyPlaying`), now passed into the injected script as `initial.forceCue`. A guest deck (sibling already live) always lands cued, regardless of its own tab's autoplay state. An anchor deck (no live sibling — solo connect, or first of a cold-start pair) is left exactly as found: idle stays cued, already-playing keeps running undisturbed. The 4s autoplay-reassert pause-guard only installs when the deck is actually being cued.
- **`swapDecks()` (`sidepanel.js`) now swaps `levelSmoothedDb.A`/`.B` along with the rest of the deck state**, same as `sendTrackToOtherDeck()` already did — this was the actual "gain stays visibly lit after swap" bug (screenshot: the 9-segment level-meter LED strip, not the gain knob). `levelSmoothedDb` is keyed by deck letter, not tabId, and `swapDecks()` swapped every other per-deck field but this one, so the meter stayed tied to the box position instead of following the track. Also: a slot left empty by a swap (trading a live deck into an unoccupied one) never runs through `disconnectDeck()`, so its meter used to freeze at the departed track's last reading forever (`startLevelsPoll` skips tabId-less decks) — now explicitly zeroed (`levelSmoothedDb[deck] = -60; setLevelMeterLit(deck, 0)`) for any deck that ends up without a `tabId` post-swap.
- Both fixes copied into `dist/GrooveMix/sidepanel.js` (was a plain mirror of the source file before this change, confirmed by diff).

**v0.4.8** — all of the above (connect force-pause fix incl. the guest-deck forceCue refinement, swap level-meter fix). First upload attempt hit `ITEM_NOT_UPDATABLE` (v0.4.7 still in review); retried once that review finished and it went through. Built from `dist/GrooveMix/` via `chrome-web-store` API upload + `publish?publishTarget=default`, both `status: OK`. Approved and live (2026-08-11).

**Open/unresolved:**
- Not yet verified live against an actual running set — fixes are grounded in tracing the exact code path the direct reports described, not confirmed by reproducing in the browser.

## 2026-08-11 — FX type selector: Delay added alongside Filter (◀/▶ arrows)

Proposed a menu of FX types buildable on stock Web Audio nodes only (no AudioWorklet — CSP blocks it on YouTube, same reason the beat detector runs on ScriptProcessorNode; no external assets either): Filter (existing), Delay, Trance-gate, Flanger, Phaser, Bitcrush, Auto-pan, Reverb. User picked Delay/Trance-gate/Reverb/Auto-pan for a future batch; this session builds the switching architecture plus the first type, **Delay** (tempo-synced echo), replacing the single always-filter FX knob. Filter behavior is unchanged.

**Audio graph (`counterDJSetup`, `sidepanel.js`):** the FX slot was a single `BiquadFilterNode` wired straight into the signal path (`eqOut → fx → gain → cross → destination`). Delay needs a parallel wet/dry mix (a pure-series delay would garble 100% of the signal, not just add echoes on top), so the slot is now a dry/wet bus: `eqOut → fxDry ⇢ fxBus` and `eqOut → [active effect] → fxWet ⇢ fxBus`, `fxBus → gain → cross → destination`. Filter stays a pure insert (`fxDry.gain=0, fxWet.gain=1`) — audibly identical to before. Delay always passes dry (`fxDry.gain=1`) with `fxWet.gain` as the knob's wet-mix amount. Delay processor: `DelayNode` (2s ceiling) + fixed 0.35 feedback gain (not exposed as a separate control — one knob per deck) in a feedback loop.

**Type switching (`counterDJSetFxType`, new):** rewires which effect feeds `fxWet` — `disconnect(dest)` must be called on the *source* node (`fx.disconnect(fxWet)`, not `fxWet.disconnect()`, which would instead sever fxWet's own output to fxBus — caught in review before shipping). Applies the type's starting value immediately so switching doesn't leave the effect silent/stale until the next knob touch. No early-return on "already this type" — `sendTrackToOtherDeck()` (below) needs it to always re-apply the value even when the type isn't changing.

**Knob semantics (`FX_TYPES`/`fxRange()`, new):** one physical knob per deck serves whichever type is active. Filter keeps its bipolar -1..1 sweep; Delay is unipolar 0..1 wet-mix. Switching types resets the knob to that type's own neutral value — carrying e.g. a +0.8 highpass position over as an 80%-wet delay mix would be a meaningless jump. `KNOB_BANDS` (drag/wheel), `PARAM_RESET` (dblclick-kill), and `NUDGE_RANGE` (hotkey nudge — `c`/`v` deck A, `n`/`m` deck B, unchanged bindings) all now resolve fx's range dynamically per-deck via `fxRange()` instead of a static table entry.

**Tempo sync:** `delayTimeForBpm()` — quarter-note spacing (`60/bpm`, clamped 0.08–1.5s) from the deck's own `detectedBpm`, refreshed via `sendParam(deck, 'fxDelayTime', ...)` whenever `pollOneDeckStatus`'s existing `bpmChanged` check fires (same hook the tempo-blend re-apply already uses). Falls back to a fixed 0.35s before any BPM locks.

**`sendTrackToOtherDeck()`:** fx is deck/box-bound like gain/EQ, so a stream move must re-push the box's fx type+value onto whichever tab just landed there — switched from a plain `sendParam('fx', ...)` to `sendFxType(deck, fxType, fx)`, or a track moving into a box currently on Delay would get its wet-amount misread as a filter sweep position by a tab whose own graph was still on Filter.

**Backward compat:** `counterDJSetup`'s reconnect branch (`window.__counterDJ__` already exists) and `counterDJSetFxType` both guard on `eng.fxWet` before touching the new bus — a tab whose graph was built by a pre-this-session extension version has no dry/wet bus at all (old direct `eqOut→fx→gain` topology), so reaching into `eng.fxWet` would throw. Same self-heal pattern the file already used for `cueAudioEl` on older tabs. Reconnect always forces `fxType` back to `'filter'` (matches `connectDecks()` resetting it on every fresh connect) so a prior session's delay routing can't survive a disconnect/reconnect.

**UI:** ◀/▶ arrows + type name replace the FX knob's old static "FX" label + LED dot, in the same row (not a separate row above the knob — cut after a first pass added one, per direct mid-session feedback). `sidepanel.html` (×2 decks), `.fxTypeBtn` in `styles.css` (bare glyph, same language as `.skipBtn`/`.phaseNudgeBtn`).

Synced to `dist/GrooveMix/` (all three files).

**Same session — Delay's dry/wet mix fixed to an equal-power crossfade (direct report, heard live):** dry was pinned at gain 1 always, wet just summed on top. Two complaints tracing to the same cause: the mix "sounds filtered" rather than distinct echo repeats, and separately "makes the signal quieter" (liked, asked to lean into it). Summing a signal with its own delayed+fed-back copy at fixed full dry *is* a comb filter by definition — that's the "sounds filtered" report explained, and it also means dry never receded to let the wet tail read as quieter/distinct. Fixed in both `counterDJSetParam`'s 'fx' branch and `counterDJSetFxType`'s delay-entry branch: `fxDry.gain = cos(θ)`, `fxWet.gain = sin(θ)` where `θ = value * π/2` — dry recedes as the knob goes up, wet comes up in its place, combined level roughly constant across the sweep (equal-power, not a linear crossfade which dips in the middle). Synced to `dist/GrooveMix/sidepanel.js`.

**Same session — the actual "sounds like a filter, not delay" cause (direct report, heard live: "doesn't sound at all", "more like a filter than a delay"):** `FX_TYPES.delay.reset` was `0` — same as `min`. Switching to Delay via the ◀/▶ arrow (`cycleFxType`) resets the knob to `reset`, landing straight on 0% wet: dry-only, which after the equal-power crossfade fix above is *acoustically identical* to Filter's own bypass (both are just a transparent `eqOut` passthrough at their respective neutral points). The two effects were genuinely indistinguishable by ear at their default landing position — not a filter-vs-delay bug, a reset-value bug. Filter's `reset: 0` is correct (true center/bypass for a bipolar sweep, matches a real isolator knob); Delay's needed to be a real audible amount instead, since selecting an effect should demonstrate it immediately, not require also dragging the knob. Changed to `0.45`. Side effect (a genuine improvement, not just incidental): `resetOrKill`'s dblclick-to-kill was degenerate for delay before this (`reset === min`, toggling 0↔0) — now dblclick meaningfully snaps to 0.45 / kills to 0. Synced to `dist/GrooveMix/sidepanel.js`.

**Same session — actual root cause found: stale tab, not a DSP bug.** User kept reporting no audible delay at all ("doesn't sound like anything", "more like a filter") even after the crossfade and reset-value fixes above. Diagnosed by asking three questions instead of guessing a fourth DSP tweak — confirmed: reloading the *extension* updates `sidepanel.js`, but a YouTube tab's `window.__counterDJ__` survives SPA navigation and is only rebuilt from scratch if it doesn't already exist. A deck connected before today's FX-type work landed still has the OLD graph (`eqOut→fx→gain` direct, no dry/wet bus at all) — `counterDJSetFxType` correctly detects this (`if (!eng.fxWet) return {ok:false, error:'FX bus missing — reconnect this deck to pick up the new FX types'}`, added earlier this session) and the user did see that exact message, just only noticed it going delay→filter, not on the initial switch. **The real fix for the user right now is a full YouTube tab reload** (not just extension reload) so the tab picks up the new `counterDJSetup` fresh-build path, then reconnect.

That said, the UI had a real bug worth fixing regardless: `cycleFxType()` updated `state.decks[deck].fxType`/`fx` optimistically and never rolled back on failure, so a rejected switch left the panel showing "DELAY" at some wet% while the tab's audio silently kept doing whatever it was doing before — turning the knob then does nothing audible, with no visual sign anything is wrong beyond a status message that's easy to miss. Made `cycleFxType` `async` and `sendFxType` return a success boolean; on failure the type/value now roll back to what they were before the click, so the UI can't claim a switch that didn't happen.

**Also this session — feedback popover alignment (direct request, then reverted):** `.feedbackPopover` `right: 16px` → `left: 16px`, then back to `right: 16px` on a follow-up request in the same round (came in alongside a "window looks like a grey surface" report — investigated `ds/tokens.css` and CSS brace-balance as possible causes of a global style failure, found nothing broken; left unresolved, see below, since the user moved on to the redesign below without confirming whether it was still happening).

**Delay redesigned from a wet-mix knob to a rate/density knob (direct request, after the stale-tab reload still didn't make it sound distinct):** even accounting for the stale-tab explanation above, the user's underlying ask was that turning the knob right should make the echo audibly *denser* — tied to BPM divided by 2, 4, 8 — not adjust how loud a fixed-rate echo is against the dry signal. Wet-amount and rate are genuinely different axes; only having wet-amount was arguably always going to read as "not really a delay" regardless of the stale-tab confusion, since a plain volume knob doesn't demonstrate rhythm.
- `delayDivisorForValue(value)` (new): `2^(value·3)` — 1x spacing at knob=0 (echoes one beat apart), 2x at 1/3, 4x at 2/3, 8x at knob=1 (eighth-of-a-beat, dense/stuttery). Continuous, not stepped, like every other knob in the mixer.
- `delayTimeForBpm(bpm, divisor)`: `(60/bpm)/divisor`, clamped to 0.04–1.5s — floor raised from the previous version's 0.08s isn't the point here, the *divisor* now does the "denser" work instead of shortening a fixed base time; floor still guards against degrading into comb-filter buzz at extreme settings.
- Wet/dry mix is now a **fixed** equal-power blend (θ=0.6·π/2) set once in `counterDJSetFxType` when Delay is selected, deliberately wet-forward so the rate change this knob now controls stays clearly audible. `counterDJSetParam`'s 'fx' branch is a no-op for delay — the knob's raw value only ever reaches the graph via `'fxDelayTime'` now.
- `refreshDelayTime(deck)` (existing, from the BPM-sync work) is now also called on every knob drag/wheel/hotkey-nudge/dblclick-reset for the fx band while `fxType === 'delay'` — previously only fired on BPM changes and on type-switch, so moving the knob itself didn't update anything audible yet.
- `sendTrackToOtherDeck()` also gained a `refreshDelayTime` call for a box on Delay — `sendFxType` sets the fixed wet blend but never touched `delayTime`, so a stream moving into a Delay-mode box would otherwise keep whatever raw delay time the incoming tab happened to have, not the box's density knob position.
- Knob title readout: `DELAY: ${ms}ms echo (÷${divisor})` — replaces the old `% wet` reading, matches what the knob now actually controls.

Synced `sidepanel.js` and `styles.css` to `dist/GrooveMix/`.

**Open/unresolved (at the time, before the FX-type work was shelved — see below):**
- Still not confirmed by ear — this redesign hadn't been tested live yet either (needed the tab-reload from the entry above, plus this new rate-based version).
- The "grey window" report above was never diagnosed — `ds/tokens.css` and `styles.css` brace-balance both checked out fine; if it recurs, need the browser console's actual error, not more guessing.

## 2026-08-11 — FX-type work shelved: fully reverted to the single Filter knob, v0.4.9 built

Explicit decision to set the whole FX-type/Delay effort aside rather than keep iterating on it live ("давай пока забьём на эффекты... просто убери и собери бандл"). Delay never got confirmed working end-to-end in this session — every round hit a different issue (stale-tab graph mismatch, wet-mix-vs-filter indistinguishability, then a mid-redesign to rate/density that was never heard at all) — so rather than ship something unverified, the whole feature was pulled back out.

**Manually reverted** (no clean git commit boundary existed between this work and the legitimate playback/tempo-bar fixes made earlier the same day in the same files, so this was a surgical code revert, not a `git checkout`):
- `sidepanel.html` (×2 decks): ◀/▶ arrows + type-name label → back to the plain "FX" label + LED dot.
- `styles.css`: removed `.fxTypeBtn`.
