# MVP Scope — Screenshotter

Прежде чем выбирать между треками: **модель распространения решена в пользу
donation/open-source, а не платной лицензии** — это Must для обоих треков
(см. `prioritization.md`, кросс-трек), обоснование в `interview_zhenya.md`.

## Трек A — менюбар-ресайзер

**Одно предложение.** Нативная menu-bar утилита, которая по хоткею готовит
скриншот под AI-чат (де-ретинизация, клемп размера) и явно показывает пользователю,
что сессия в безопасности, вместо того чтобы узнавать это постфактум.

**Фичи MVP (только Must have).**
- Два режима размера (Full-size / AI-optimized) — уже реализовано
- Индикатор активного режима до/во время захвата
- Дефолтный хоткей, не совпадающий с системным
- Счётчик «скриншотов за сессию»
- Free trial / free tier

**Основной сценарий (путь Оли).** Долгая debug-сессия в Cursor → жмёт хоткей →
видит HUD с текущим режимом и счётчиком скриншотов за сессию → делает снимок →
вставляет в чат, уверенная, что не спровоцировала обрыв сессии → к концу дня
не видит ни одного «session died».

**Что осознанно НЕ входит (топ-3 Should have).**
1. **Автоопределение целевого приложения/режима** — полезно, но ручной режим уже
   рабочий fallback; авто-детект требует интеграции с конкретными приложениями
   (Cursor, Claude), это отдельный виток инженерной работы после проверки MVP.
2. **Объяснение ограничения shadow-тумблера** — улучшает доверие, но не блокирует
   основной сценарий (сессионная боль), можно добавить в патче.
3. ~~Полная адаптивная эскалация сжатия~~ — **удалена из скоупа целиком**, не просто
   отложена: техпроверка 2026-08-21 показала, что честно точные данные о контексте
   сессии доступны только для Claude Code, не для остальных целевых IDE-агентов —
   обещание, работающее на одном инструменте из нескольких, не решение.

## Трек B — контекст-менеджер для агентов

**Одно предложение.** Self-hosted MCP-инструмент, позволяющий Claude Code/Cursor
самостоятельно запрашивать точный, откалиброванный под Computer Use снимок экрана —
без промахов курсора и без слепой траты токенов.

**Фичи MVP (только Must have).**
- Локальный / self-hosted MCP-сервер
- Нормализация под фиксированные Computer Use разрешения (1024×768 / 1280×720)
- Явный функциональный дифференциатор от Screentack
- Free trial / free tier (или сразу open-source)

**Основной сценарий (путь Стаса).** Строит агентский pipeline с Computer Use →
подключает наш MCP-сервер локально → агент сам запрашивает скриншот через
MCP-инструмент → получает уже нормализованный под 1024×768 снимок → кликает по
верным координатам без промахов → Стас не видит смещений на 20–40px.

**Что осознанно НЕ входит (топ-3 Should have).**
1. **Статический калькулятор стоимости снимка в токенах** — сильная рыночная фича
   (никто её не делает) и честно универсальная (формулы платформы, без доступа к
   сессии), но не dealbreaker в интервью; точность координат важнее для первого
   релиза, экономия токенов — следующий шаг.
2. **Точный остаток контекста сессии (только Claude Code)** — техпроверка 2026-08-21
   подтвердила это технически возможным именно для Claude Code (statusline API,
   локальные `.jsonl`), но продавать это как общую фичу продукта нечестно —
   реализуется позже как явно промаркированный нишевый бонус, не в MVP.
3. **Разрешение гонки ручного/агентского запроса** — важно для надёжности при
   параллельной работе, но не блокирует первый релиз с одним основным потребителем
   запроса (агентом).

## Что решить перед выбором трека

Оба MVP технически валидны по интервью, но решают разные боли и требуют разного
объёма работы (A — доработка существующего кода; B — новый MCP-сервер с нуля).
Итоговое сравнение и рекомендация — в `prd.md`.
