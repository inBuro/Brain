# PRD — Screenshotter v1.0

## 1. Executive Summary

Screenshotter — нативная menu-bar утилита, готовящая скриншоты под вставку в AI-чат.
Проблема (бриф): в длинных AI-сессиях, особенно в IDE-агентах, Retina-скриншоты
съедают контекстное окно быстрее, чем должны, обрывая сессию раньше времени.
Ключевой инсайт исследования: рынок уже занят — минимум два продукта формулируют ту
же боль дословно, один из них полностью бесплатный, и рынок активно движется к
MCP-агентской интеграции (Screentack, растёт) и структурным данным вместо картинок
(SlimSnap), а не к статичному ресайзу. Решение (`mvp_scope.md`) существует в двух
вариантах — **план A** (доработанный менюбар-ресайзер) и **план B** (пивот в
self-hosted MCP-менеджер контекста/точности) — и ни один не пережил интервью
персон без изменений. Primary-персона плана A — Оля (её JTBD оказался сессионным, не
пофайловым); primary-персона плана B — Стас (его JTBD — точность кликов агента, не
экономия токенов как таковая).

**Итоговая рекомендация — см. раздел 8.** Коротко: план A как платный продукт не
защитим; план B защитим сильнее, но требует нового инженерного объёма и не решённой
дифференциации от Screentack; общая для обоих находка — модель распространения
должна быть donation/open-source, а не разовая лицензия $20.

## 2. Цели и метрики

**Objective 1 — Подтвердить или закрыть гипотезу продукта до вложения $100+времени.**
(Эта цель уже достигнута этим исследованием.)
- KR1: Найдено ≥5 прямых/косвенных конкурентов — 7 найдено.
- KR2: Проверено на ≥2 персонах через симулированное интервью — 3 персоны, 3 интервью.
- KR3: Получен явный go/no-go сигнал по цене — получен (оба paid-плана отвергнуты
  price-sensitive персонами).

**Objective 2 — Если продолжаем (после выбора трека): убрать «тихие» UX-провалы,
из-за которых пользователь не доверяет продукту.**
- KR1: 0 конфликтов дефолтного хоткея с системными хоткеями macOS.
- KR2: 100% захватов сопровождаются видимым индикатором режима/уровня компрессии
  до или во время захвата (не только постфактум).
- KR3: Session-стрик «дошёл до конца долгой сессии без session died» отслеживается
  хотя бы вручную (self-report), пока нет телеметрии.

**North Star (кандидат, требует выбора трека для финализации):** доля AI-сессий
пользователя, завершённых без принудительного «session died» — прокси для JTBD
обеих primary-персон, работает независимо от того, какой трек выбран.

## 3. Целевая аудитория

- **Оля — frontend-разработчица (primary для плана A).** Работает в Cursor,
  скриншотит по 10-15 раз за долгую debug-сессию, сейчас пользуется системным ⇧⌘4.
  JTBD: чтобы скриншоты не обрывали сессию — но по интервью это сессионная, а не
  пофайловая боль, и статичный ресайз одного изображения её не убеждает.
- **Стас — инженер, строит собственных AI-агентов (primary для плана B).**
  Работает с MCP ежедневно, сталкивается с промахами курсора агента на 20–40px из-за
  серверного масштабирования Retina-скриншотов. JTBD: чтобы агент сам получал точный
  снимок без участия человека. Секьюрити/приватность (self-hosted, не облако) —
  жёсткое условие, не пожелание.
- **Женя — инди-разработчик, бюджетно-чувствительна (secondary, стресс-тест цены
  для обоих треков).** Уже знает конкретные бесплатные альтернативы по именам
  (Image Resizer for Claude Code, SlimSnap, pxpipe). Отвергла one-time лицензию $20
  для обоих планов, предпочла donation/open-source.

## 4. Конкурентный ландшафт

Семь конкурентов, три философии решения одной боли: пиксельный ресайз (мы, Image
Resizer for Claude Code, отчасти LazyScreenshots), структурные данные вместо картинки
(SlimSnap), агентский MCP-доступ (Screentack). Полная версия —
`competitive_analysis_final.md`.

| Дифференциатор | У кого уже есть | У нас (план A) | У нас (план B) |
|---|---|---|---|
| Нативный menu-bar + хоткей | Большинство (5/7) | ✅ (уже есть) | ✅ |
| Статичный ресайз/де-ретинизация | LazyScreenshots (частично), Image Resizer (бесплатно) | ✅, но не уникально | ✅, не уникально |
| Статический калькулятор стоимости в токенах (без доступа к сессии) | Никто | ❌ | ✅ — уникально, честно универсально |
| Точный остаток контекста сессии | Никто | ❌ | ⚠️ — технически только для Claude Code (техпроверка 2026-08-21), не продаётся как общее обещание |
| MCP-доступ для агента | Screentack, SlimSnap (частично) | ❌ | ✅, но не первый на рынке |
| Нормализация под Computer Use | Никто из сторонних тулов | ❌ | ✅ — уникально |

## 5. MVP Scope

Полная версия — `mvp_scope.md`. Кратко: **план A** — доработанный менюбар-ресайзер с
индикатором режима, разведённым хоткеем и счётчиком скриншотов за сессию, плюс free
tier. **план B** — self-hosted MCP-сервер с нормализацией под Computer Use и явным
функциональным отличием от Screentack, плюс free tier/open-source.

**Что осознанно не входит в MVP ни одного из треков (v1.1):** автоопределение
целевого приложения (A), статический калькулятор стоимости в токенах (B), точный
остаток контекста сессии для Claude Code как нишевый бонус (B) — см. обоснование в
`mvp_scope.md`. Сессионная «адаптивная эскалация сжатия» как общее кросс-платформенное
обещание удалена из скоупа целиком, не просто отложена — см. раздел 8.

## 6. User Stories

**Must have, план A:**
- Как Оля, я хочу видеть текущий режим (Full-size/AI-optimized) до захвата, чтобы не
  отправить не тот файл. *AC: HUD с названием режима виден одновременно с crosshair,
  до выделения области.*
- Как Оля, я хочу, чтобы хоткей приложения не совпадал с системным ⇧⌘4, чтобы не
  путать источник скриншота. *AC: дефолтный хоткей отличается от всех системных
  hotkeys `screencapture`; уникальность проверяется при первом запуске.*
- Как Оля, я хочу видеть счётчик скриншотов за текущую сессию, чтобы понимать
  накопленный риск. *AC: счётчик сбрасывается по сигналу «новый чат» (ручному) или по
  таймауту бездействия; виден в меню.*
- Как Оля, я хочу попробовать бесплатно, прежде чем платить. *AC: free tier или
  триал ≥7 дней без ограничения функций режима AI-optimized.*

**Must have, план B:**
- Как Стас, я хочу, чтобы MCP-сервер работал локально, без облака, чтобы не
  передавать содержимое экрана третьей стороне. *AC: сервер поднимается и
  функционирует полностью офлайн, без исходящих сетевых вызовов при захвате.*
- Как Стас, я хочу, чтобы скриншот автоматически нормализовался под 1024×768 или
  1280×720 для Computer Use, чтобы агент не промахивался кликами. *AC: измеримое
  снижение расхождения координат клика относительно исходного clic-target на
  тестовом наборе экранов.*
- Как Стас, я хочу понимать, чем это лучше Screentack, чтобы обосновать выбор.
  *AC: минимум одна задокументированная функциональная разница, не только
  «self-hosted vs $29», проверенная на реальном use-case.*

## 7. Нефункциональные требования

- **Платформа:** macOS-only, Objective-C (Swift не собирается на машине сборки —
  зафиксировано в `wiki/internals.md`). Кроссплатформенность (Linux) явно вне
  скоупа — поднято Женей в интервью, не решается в этой версии.
- **Приватность (план B):** MCP-сервер обязан быть self-hosted/локальным — жёсткое
  требование из интервью Стаса, не опция.
- **Производительность:** захват должен оставаться асинхронным (уже так реализовано,
  `internals.md`) — не блокировать никакой run loop, включая MCP-запросы агента.
- **Распространение:** donation/open-source вместо разовой платной лицензии —
  см. раздел 8 и `interview_zhenya.md`.

## 8. Риски и открытые вопросы

**Из конкурентного анализа (угрозы):**
- План A полностью воспроизводим бесплатным open-source аналогом (Image Resizer for
  Claude Code) — цена не защитима исполнением, только UX-полировкой.
- План B входит в уже растущую нишу с прямым конкурентом (Screentack) — не пустое
  поле.

**Из интервью (противоречия с исходными допущениями):**
- Допущение «статичного ресайза достаточно» — не подтвердилось даже у Оли
  (primary для плана A): её боль сессионная, не пофайловая.
- Допущение «адаптивная эскалация сжатия — понятная фича» — не подтвердилось у
  Стаса: без доступа к реальному бюджету токенов модели это эвристика, которую
  нужно показывать прозрачно, а не выдавать за точный расчёт.
- Допущение «one-time покупка $20 — рабочая модель» — отвергнуто и Олей, и Женей;
  подтверждается независимо рекомендацией Gemini (deep research, «Вариант A»).

**Из техпроверки телеметрии (2026-08-21) — сузило скоуп плана B:** точные данные о
контексте сессии (statusline API, локальные `.jsonl` транскрипты) доступны только для
Claude Code; для Cursor нет стабильного API (недокументированная SQLite-схема,
хрупко); для ChatGPT/Claude.ai веб-доступа нет вовсе — OpenAI намеренно скрывает
заполненность контекста, сторонние расширения лишь оценивают по видимым сообщениям.
Прямая оценка пользователя: «обещание, работающее только на одном инструменте из
нескольких целевых, — не решение, а невыполненное обещание». Сессионная адаптивная
эскалация удалена из скоупа как общая фича; взамен — статический калькулятор стоимости
снимка (не требует доступа к сессии, честно работает везде), а точный остаток
контекста остаётся только как явно промаркированный Claude-Code-only бонус.

**Вопросы, требующие реального кастдева (не закрываются синтетическими данными):**
- Реальная частота проблемы «context overflow от скриншотов» среди случайных
  пользователей (сейчас — вторичные данные и качественные сигналы, не количественные).
- Готовность реальных (не синтетических) пользователей задонатить за open-source
  версию — конверсия donation-модели не проверена на реальных людях.
- Функциональная дифференциация от Screentack для плана B — сейчас не решена даже на
  уровне идеи, не то что реализации.
