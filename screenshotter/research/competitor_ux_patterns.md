# UX Patterns — Screenshotter

## 1. Рыночный стандарт

Что делают одинаково почти все нативные конкуренты (LazyScreenshots, CleanShot X,
Shottr, SlimSnap, Screentack) — это ожидания пользователя по умолчанию:

- **Menu-bar + глобальный хоткей**, без запуска отдельного окна для каждого захвата.
- **Разовая покупка, не подписка** — исключение только облачные надстройки
  (CleanShot Cloud Pro), которые продаются отдельно от базовой лицензии.
- **Нулевой/минимальный онбординг** — сразу в работу из трея, без мастеров настройки.
- **Результат в буфере обмена сразу после захвата** — общий паттерн независимо от
  того, что именно дальше происходит с картинкой.

## 2. Точки расхождения

Где конкуренты решают одну и ту же задачу принципиально по-разному:

- **Автоматизация цепочки «захват → вставка».** LazyScreenshots и Screentack
  автоматизируют её полностью (авто-детект вкладки/приложения + вставка одним
  хоткеем). Остальные, включая наш план A, оставляют вставку на пользователя.
- **Природа «оптимизации под AI».** Три разных философии: пиксельный ресайз (мы,
  Image Resizer, план A) vs замена картинки структурными данными — JSON (SlimSnap)
  vs агентский MCP-доступ, вообще без ручного скриншота человеком (Screentack).
  Это не вариации одного паттерна, а разные ответы на вопрос «что вообще отправлять
  модели».
- **Прозрачность стоимости.** Ни один из семи конкурентов не показывает пользователю
  явную стоимость снимка в токенах перед отправкой — рынок стандарта здесь не
  выработал, это открытая точка, не занятая ниша.

## 3. Рекомендации

- **Взять у LazyScreenshots/Screentack** (для плана B, при необходимости и для A):
  авто-детект целевого приложения — не обязательно полный авто-паст, достаточно
  индикатора «скриншот подготовлен под AI», чтобы снизить тревогу пользователя за
  судьбу сессии без риска конфликтовать с чужими флоу (риск авто-паста, отмеченный
  в SWOT LazyScreenshots).
- **Взять у SlimSnap:** конкретную числовую коммуникацию экономии («700 токенов
  вместо 4784»), а не абстрактное «оптимизировано для AI» — конкретное число убедительнее.
- **Не брать у CleanShot X / Xnapper:** перегруженное меню с десятками режимов
  записи/аннотации. Простота — наш текущий плюс (Phase 0 уже минималистична), плодить
  настройки не стоит даже при пивоте в B.
- **Для плана B обязательно взять MCP-паттерн** Screentack/SlimSnap — агент сам
  запрашивает скриншот через MCP-инструмент, а не человек вручную жмёт хоткей. Это
  уже не экспериментальный, а ожидаемый паттерн у продвинутой части аудитории.
