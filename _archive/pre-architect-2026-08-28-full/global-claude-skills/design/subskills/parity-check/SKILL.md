# Аудит совпадения React ↔ Figma (parity-check)

## Цель
Формальный аудит совпадения React ↔ Figma для текущего проекта.

## Шаги
0. Найти в текущем проекте: файл-индекс компонентов (обычно `src/components/index.ts` или `app/src/components/index.ts`; если не находится по частым путям — спросить пользователя) и файл токенов (обычно `tokens.json` или `src/tokens/*.json`; аналогично уточнить, если не очевидно). Ссылку/node_id на страницу компонентов в Figma — из контекста задачи или спросить.
1. Прочитать список компонентов из найденного индекс-файла.
2. Через `mcp__figma__get_metadata` получить список Component Set / Component на странице компонентов в Figma.
3. Сравнить:
   - Имя 1:1 (Button === Button, не button-primary)
   - Variant property names совпадают с React prop names
   - Variant value sets совпадают (например, Variant=primary|secondary|ghost для Button)
4. Прочитать файл токенов и сравнить с Figma Variables (через `mcp__figma__get_variable_defs`).
5. Записать отчёт в `artifacts/parity-report.md` (относительно корня текущего проекта — создать `artifacts/`, если её нет) в формате:
   ```
   ## Колонки
   - ✅ Совпадает
   - ⚠️ Расхождение (с описанием)
   - ❌ Только в коде / только в Figma
   ## TODO
   - список конкретных правок для приведения к 1:1
   ```

## Запускать
После каждой значимой итерации (новый компонент, изменение токена, рефакторинг) в любом React-проекте с Figma design-системой.
