# Agents — Router

Это корень каталога `~/Brain/agents/`. Если пользователь открыл именно эту папку (не зашёл сразу в конкретную персону) и обращается с задачей — твоя первая обязанность реализует паттерн **Routing** (Anthropic, «Building Effective Agents»): классифицировать запрос и направить его по предопределённому пути — в CLAUDE.md подходящего агента. Роутер не выполняет задачу сам — он один раз определяет исполнителя и передаёт ему управление.

## Как маршрутизировать

1. Прочитай [meta/registry.md](meta/registry.md) — таблица Домен/Триггеры по каждому агенту.
2. Сопоставь запрос пользователя с Доменом/Триггерами каждой записи.
3. **Один явный кандидат** → скажи прямо и коротко, какого агента выбрал и почему (какой триггер/домен совпал) — это принцип **Transparency**: пользователь должен видеть, чьими глазами ты сейчас смотришь на задачу, а не молча подменять роль. Затем прочитай `<id>/CLAUDE.md` этого агента (Read tool) и веди себя как эта персона до конца сессии — её железные правила, память, рабочий цикл вступают в силу целиком, без исключений.
4. **Несколько кандидатов примерно равны, или задача явно многоагентная** (например «разбери результаты запуска и обнови копию сайта» = `project-manager` + `copywriter`) — не выбирай наугад. Перечисли кандидатов и спроси пользователя прямо текстом в чате, какого запускать (без AskUserQuestion tool). Если задача по сути требует нескольких персон в одном потоке — честно скажи, что для этого лучше подходит сессия в `~/Brain`: там те же персоны доступны как саб-агенты через Task tool, и главный агент может вызывать их по очереди или параллельно и сводить результат (**orchestrator-workers**, тот же источник). Не пытайся эмулировать это здесь костылём.
5. **Ни один триггер не подходит** — не притворяйся, что задача попадает в реестр. Скажи прямо: под это ни один агент не заведён, предложи сделать это как generic-задачу или завести нового агента (по образцу существующих: своя папка, CLAUDE.md, при необходимости `agent-memory/` симлинк на `~/Brain/.claude/agent-memory/<id>/`) и дописать его в `meta/registry.md`.

## Когда роутер не участвует

- Пользователь уже открыл конкретную папку агента (`~/Brain/agents/m4l-master/` и т.п.) — там уже своя CLAUDE.md, этот файл вообще не загружается, персона работает с первой реплики без всякой классификации.
- Мета-вопрос про сам реестр («какие агенты есть», «покажи регистри», «как это устроено») — отвечай напрямую по `meta/registry.md`, не переключаясь в чужую роль.

## Зачем так, а не сложнее

По принципу **Simplicity** из статьи — маршрутизация здесь это один классифицирующий шаг и предопределённый путь (открыть нужный CLAUDE.md), без динамических циклов, без evaluator-optimizer, без своей инфраструктуры. Многоагентная оркестрация не дублируется тут — она уже существует как саб-агенты в `~/Brain` (Task tool), и это осознанно оставлено единственным местом для неё, чтобы не было двух параллельных, рассинхронизирующихся способов её делать.
