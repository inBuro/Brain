# Frontend — роутер группы

Подскиллы лежат в `subskills/<имя>/SKILL.md` — прочитай нужный и работай по нему. Один инструмент группы — официальный Anthropic-плагин, вызывается напрямую по plugin-имени, без локальной копии.

| Задача | Подскилл |
|---|---|
| Собрать production-grade фронтенд с чёткой эстетикой, лёгкий вход, greenfield-компонент/страница | плагин `frontend-design:frontend-design` (Skill tool, вызывать прямо по имени — не через путь группы) |
| Собрать/раскритиковать/отполировать/анимировать фронтенд (20+ команд, тяжёлый тулчейн, живая браузер-итерация) | impeccable |
| Почистить сгенерированный код (HTML/CSS/Tailwind/React) от ИИ-слоп-паттернов — audit/fix, есть и визуальный режим по скриншоту | design-anti-slop |

## Кто исполняет

Персона **frontend-designer** (`~/Brain/agents/frontend-designer/CLAUDE.md`, форвардер `~/.claude/agents/frontend-designer.md`) — единственный держатель этой группы: пишет и правит настоящий код, источник продуктовых/визуальных решений — спецификация от `ux-ui-designer` (группа `design`), не изобретает их сам. После сборки код можно сверить с Figma через `parity-check` (остаётся в группе `design` — это read-only аудит соответствия, не сборка).

## Дедуп-вахта

- **frontend-design (плагин) vs impeccable**: не сливать — разные веса. Плагин — лёгкий вход без внешних зависимостей, `impeccable` — тяжёлый вендорский тулчейн (Apache 2.0, свои `reference/`+`scripts/`, 20+ команд, требует `npx impeccable`, «Based on Anthropic's frontend-design skill»). Если плагин месяцами не зовётся отдельно от `impeccable` — не повод ничего пенсионировать, плагин живёт вне этой группы и обновляется сам.
- **design-anti-slop vs dev-toolchain/gstack (design-review)**: разный метод на одну проблему (слоп в UI) — `design-anti-slop` работает по каталогу через grep/diff кода, `gstack design-review` — визуально через headless-рендер живой страницы. Держать оба, не сливать (gstack — вендорский пак в другой группе).
