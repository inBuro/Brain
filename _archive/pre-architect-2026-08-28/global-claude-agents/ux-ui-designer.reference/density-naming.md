# Density-шкала: правило именования

Если в проекте используется density-based spacing scale (1 unit плотности = константа в px, типично 4px), действует строгая конвенция имён:

**Имя density-токена — это только число. Без префиксов, без слэшей, без групп, без суффиксов.**

- Имя переменной в Figma = значение плотности: `0`, `0,25`, `0,5`, `1`, `1,25`, `12,5`, `15,5`.
- Имя CSS-переменной = то же значение, разделитель дроби в CSS — дефис: `--0`, `--0-25`, `--1`, `--12-5`.
- Никакого префикса коллекции (`--density-*`, `--d-*`) в CSS — само число достаточно осмысленно.
- **Разделитель дробной части:** **запятая** (`,`) в Figma, **дефис** (`-`) в CSS. Точка `.` запрещена Figma Plugin API (`invalid variable name` при `setName`), это вынужденное ограничение, а не предпочтение.
- Минимальная гранулярность — `0,25` (= 1px при 4px-единице).
- Формула: `px = density × base-unit` (где base-unit обычно = 4).
- Группы/слэши в имени **не использовать** — переменные лежат плоско в коллекции (типично `Density`).

**Стандартный density-ряд (канон):**

Рекомендуемые ступени для любого проекта с density-шкалой. Минимальный шаг — `0,25` (= 1px). Шаг укрупняется по мере роста значения: тонкая гранулярность нужна только на малых размерах (бордеры, иконки, тонкая типографика), на крупных — нет.

Это рекомендация, не контракт. Проект может:
- **Сократить** ряд, оставив только используемые ступени (предпочтительно — каждая ступень должна оправдывать существование).
- **Расширить** новыми дробями (например `4.25` если действительно нужно 17px) — но сначала проверить, не починит ли проблему откат к ближайшей стандартной ступени.

Проектные дополнения и отклонения фиксируются в `decisions/density-naming.md` проекта.

**Маппинг Figma → CSS:**

| Figma name | CSS variable | px |
|---|---|---|
| `0` | `--0` | 0 |
| `0,25` | `--0-25` | 1 |
| `1` | `--1` | 4 |
| `1,25` | `--1-25` | 5 |
| `12,5` | `--12-5` | 50 |
| `15,5` | `--15-5` | 62 |

Запятая в Figma → дефис в CSS. Никаких префиксов (`d-`, `density-`, `space-`) — число само себя называет.

**Чего не делать:**
- **Суффиксы** (`dense`, `tight`, `compact`) — нарушают правило. Коллизия в имени = шкала неправильна, не латать суффиксом.
- **T-shirt sizing на density-токенах** (`xs/sm/md/lg/xl`) — отвергнуто как способ имени плотности. T-shirt допустимо только для семантических алиасов (`radius-md`, `--page-pad`), не для density.
- **Слитная запись без разделителя** (`125` для 1,25) — даёт коллизию `1,25 ↔ 12,5`.
- **Точка** как разделитель в Figma — невозможно технически (Plugin API запрет).
- **Underscore** вместо запятой в Figma — отвергнуто.
- **Префикс коллекции в CSS** (`--density-6`, `--d-6`) — не использовать. CSS-имя = `--6`. Семантику передаёт имя коллекции в Figma, не имя переменной.
- **Группы/слэши** (`d/6`, `density/6`) — переменные плоско в коллекции.

**Когда добавляешь новый density-токен:**
1. Перевести px → density: `value / base-unit`.
2. Имя = `<density>` с запятой (Figma) / дефисом (CSS) если дробь.
3. Никогда не добавлять описательных хвостов «для смысла».

Это правило универсально для любого проекта с density-шкалой. Если density-шкала отсутствует или используются legacy-имена — фиксируй как technical debt в `decisions/`, мигрируй немедленно.

### Density самодостаточна — отдельный spacing-слой избыточен

Density-числа сами по себе осмысленны: `--6` = 24px = шесть units density. Это лучше любого `space-md` / `space-section-gap` — без выученной семантики, без коллизий с шкалой.

**Дефолт:** в проекте есть только Density. Spacing как отдельный слой токенов не нужен.

**Когда вводить семантические алиасы:**
- `--page-pad`, `--page-max`, `--radius-md` — это **алиасы конкретных use-cases** (страничный padding, табличный гаттер, средний радиус), они полезны и имеют смысл вне density-шкалы.
- Не для «средних отступов в общем» — для этого используется напрямую density.

**Когда обнаружил параллельный `--space-*` слой:**
- Если он содержит raw px — это технический долг, удалить.
- Если он содержит ссылки на density, но имена numeric (`space-1..10`) или t-shirt — слой избыточен, заменить consumers на density напрямую.
- Семантические алиасы по use-case (`--page-pad`, `--card-padding`) могут остаться, если оправдывают существование.
